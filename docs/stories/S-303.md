# S-303 — Post-meal reading + test-time prompt

**Epic:** 3 (Logging & Durability) · **Safety story:** No · **Status:** Done

## Story
Two things: (1) after logging a meal, prompt her to test at **reported mealtime +
120 min** — her phone alarm does the reminding (`05b §3.1`); (2) capture the
post-meal reading in **< 15 s** — one number, one **reported** time — from which
`elapsed_min` and validity are computed. Late/retrospective entry is supported:
the system **asks** for the real reading time, it never assumes it.

## Requirement sources
- **REQ-010** — post-meal BG entry takes **< 15 s**.
- **REQ-011** — late/retrospective entry supported; asks the real time, never
  assumes.
- **REQ-014** — after logging, show the time to test = **meal time + 120 min**.
- `05 §1` (`PATCH /api/meals/{id}/post-bg`), `05b §4`.

## Design
- **`PATCH /api/meals/{id}/post-bg`** — `post_bg` + `post_bg_time` (required,
  reported) + optional `hypo_treatment`/`hypo_treatment_g`/`snack_during_window`.
  Uses the S-202 `record_post_bg` (elapsed from reported times) and the S-203
  `annotate_validity` (all applicable reasons; `elapsed_min` stored even when
  invalid). Returns `{ meal_id, elapsed_min, is_valid, exclusion_reasons }`. The
  record is committed whether valid or not (adherence cannot be diagnosed from
  discarded data — `03 §2`).
- **Test-time prompt** — already returned by `POST /api/meals` as
  `test_at = reported datetime + 120` (S-301). S-303 locks the "10:00 not 11:40"
  behaviour with a focused test.
- **Post-BG form** — `GET /meals/{id}/post-bg`: BG now + "Taken at" (reported,
  **editable, never assumed**), optional "did you treat a low". Submits the PATCH.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_post_bg_api.py`:
- `PATCH …/post-bg` for an 08:00 meal with `post_bg_time` 10:05 ⇒
  `elapsed_min == 125`, `is_valid == true`.
- `post_bg_time` absent ⇒ **422** (never assumed).
- A reading that lands outside the window (elapsed 220) ⇒ `is_valid == false`,
  `exclusion_reasons` contains `outside_window`, **and the record is stored** (its
  `post_bg` persists).
- Unknown meal id ⇒ 404.
- **REQ-014:** `POST /api/meals` logged at 09:40 for an 08:00 meal ⇒ the prompt /
  `test_at` is **10:00**, not 11:40 (reported mealtime + 120, never
  `logged_at + 120`).

`tests/e2e/test_post_bg_flow.py`:
- The post-BG form carries an **editable, reported** "taken at" time and, on
  submit, shows a confirmation — the retrospective path asks, never assumes.

**RED evidence:** the PATCH route / post-BG form absent ⇒ tests fail.

**Adversarial angle:** defaulting `post_bg_time` to `now()` would fabricate
`elapsed_min` for every late entry — the same ADR-8 corruption. The required
field + the S-105 guard keep it honest.
