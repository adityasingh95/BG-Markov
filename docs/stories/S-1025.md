# S-1025 — One command from a cold laptop

**Epic:** 11 · **Safety story:** No · **Status:** In progress (2026-08-06) ·
**Requirements:** `06 §7` · **Records:** DL-063

> The operator has the repo cloned on the right branch and still cannot run it, because the
> machine is missing Python 3.12. `INSTALL.md` explains what to do about that in prose. This
> story makes it a command.

## Story
`./bootstrap.sh` takes a cold machine to a running app: it checks, offers to install what is
missing, updates the checkout, and starts the server.

---

## Why this is not just `start.sh` with more steps

`start.sh` assumes the machine is ready and *reports* when it is not. That was the right
design — a missing prerequisite becomes a sentence rather than a traceback — but it stops
one step short of the thing the operator actually needs, which is for the prerequisite to be
installed.

The gap is real and was observed: `doctor` printed
`no Python 3.12 found (tried python3.12, python3, python, py -3.12)`, which is accurate,
actionable, and still left the operator to go and find an installer by hand.

### The three things this script must not get wrong

**1. It installs software. That is not a step to take quietly.**
Every installer invocation is behind a typed confirmation. Not `-y`, not a flag that
defaults to yes. The operator sees the exact command that is about to run, on his machine,
before it runs.

**2. A new interpreter is invisible to the shell that installed it.**
`PATH` is read when the shell starts. After installing Python the running Git Bash session
still cannot see it, so a script that installs and then presses on will fail in a way that
looks like the install failed. It must stop and say *reopen your shell*, which is a worse
user experience and the only correct one.

**3. `git pull` over uncommitted work.**
The operator's checkout is where he will have been poking at things. A bootstrap script that
pulls unconditionally can fail mid-merge and leave the tree in a state he did not ask for
and cannot easily read. Dirty tree ⇒ skip the pull, say so, carry on.

## Acceptance criteria

1. `./bootstrap.sh` on a ready machine: updates the checkout and starts the app.
2. On a machine with no Python 3.12: names the missing prerequisite and **offers** the
   platform-correct install command.
3. **No installer runs without a typed confirmation.** Declining exits non-zero, having
   installed nothing.
4. After an install it **stops** and tells the operator to reopen the shell. It does not
   attempt to continue in a shell whose `PATH` predates the install.
5. A dirty working tree skips the `git pull`, with a message. It is never a hard failure.
6. `--no-start` runs every check and stops before serving, so the script is testable.
7. Subject to the same portability guards as `dev.sh` and `start.sh` (bash 3.2, no
   `.venv/bin`, no GNU-only tools).

## TDD strategy (SDET first — written and seen to fail)

`tests/integration/test_bootstrap_script.py`

- **★ Declining the offer installs nothing.** Run with a stubbed `PATH` where no interpreter
  answers to 3.12 and where `winget`/`brew`/`apt-get`/`sudo` are sentinel-writing stubs.
  Answer `n`. Assert non-zero exit **and that the sentinel does not exist** — the exit code
  alone would pass for a script that installed and then failed.
- **★ Accepting stops, and says why.** Answer `YES`; assert the sentinel *is* written, the
  output tells the operator to reopen the shell, and the app is **not** started.
- **★ A dirty tree is not pulled over.** A throwaway clone with an uncommitted change; assert
  the pull is skipped and reported, and the run still succeeds.
- `bootstrap.sh` joins `_ENTRY_SCRIPTS`, inheriting the `.venv/bin` guard.

**Adversarial angle.** (a) An installer reached by any path that skips the prompt — the test
asserts on the *sentinel*, not on the exit code, because those come apart. (b) Continuing
after an install "because it probably worked", which produces a confusing second failure in
place of a clear instruction. (c) `git pull --force`/`reset --hard` sneaking in as a way to
make the dirty-tree case "just work".
