# S-802 [SAFETY] — Prediction log

**Epic:** 8 (Guardrails & Output) · **Safety story:** Yes · **Status:** In progress ·
**Requirements:** REQ-045, **INV-9**

> **A prediction that is shown but not recorded is a silent low waiting to happen.** If
> the model tells her "you're fine" and that prediction is never written down, there is no
> way — ever — to learn it was wrong, no shadow-mode analysis, no accountability. So the
> ordering is absolute: **write first, return second.** If the write fails, nothing is
> returned. Not a degraded prediction, not a cached one — nothing.

## Story
Persist every prediction to `prediction_log` **before** it is returned to any caller, and
make that ordering **enforced, not incidental**: the write happens, its row id is
confirmed via INV-9, and only then is the prediction returned. If persistence fails, the
function raises and returns no prediction.

## Requirement source
- **REQ-045 / INV-9** — every prediction is written to `prediction_log` **before** it is
  returned.
- **08 scenario / backlog** — *"Mock the persistence layer to fail ⇒ assert NO prediction
  is returned. Write-then-display ordering is enforced, not incidental."*
- **04 §8** — the system clock **is** correct for `prediction_log.created_at` (a log
  timestamp, not a clinical event time — ADR-8 does not apply here).

## Design
`data/predictions.py` (data layer; imports `core.safety` for INV-9 and
`models.guardrails` for the guarded result):

- **`record_prediction(session, *, model_version, gate_state, input_features,
  predicted_distribution, baseline_state, meal_id=None, guardrail_fired=None) ->
  PredictionLog`** — constructs the `PredictionLog` row, `session.add(row)`,
  **`session.flush()`** (writes to the DB and assigns `prediction_id`), then
  **`inv9_prediction_persisted(row.prediction_id)`** — which raises if the write produced
  no row. Only after that check does it return the row. There is no path that returns
  before the flush + INV-9 check.
- **`ServedPrediction`** — `prediction_id: int`, `guarded: GuardedPrediction`: what a
  caller receives, and it is only ever constructed *after* the persist.
- **`serve_prediction(session, guarded, *, model_version, gate_state, input_features,
  meal_id=None) -> ServedPrediction`** — maps a `GuardedPrediction` (S-801) to the log
  fields (serialising the distribution and the fired guardrail reason), calls
  `record_prediction` **first**, and returns the `ServedPrediction` only after the write is
  confirmed. This is the write-before-display contract wired end-to-end.

**Ordering, not hope.** The flush and the INV-9 check are the first things that touch the
outside world; the return statement is physically after them. A persistence failure —
`flush()` raising, or a write that yields no id — stops the function before any prediction
escapes.

## Written safety argument (why an unlogged prediction cannot escape) [SAFETY]
1. **Write precedes return, structurally.** `record_prediction` flushes the row and calls
   `inv9_prediction_persisted` *before* its `return`. There is no earlier return and no
   alternate branch that yields a prediction — the only way out with a value is through a
   confirmed write.
2. **A failed write raises, it does not degrade.** If `flush()` raises (DB error), the
   exception propagates and the function returns nothing. If the write somehow yields no
   `prediction_id`, INV-9 raises `SafetyViolation`. Either way the caller gets an error,
   never an unlogged prediction.
3. **`serve_prediction` inherits the guarantee.** It constructs the `ServedPrediction`
   only from the row `record_prediction` returned, so it cannot hand back a prediction
   that was not persisted first.
4. **The log is the audit trail.** Because every returned prediction is in
   `prediction_log`, a later "you said I was fine" can always be checked against what the
   model actually said, with its inputs and gate state — the accountability that makes a
   wrong-about-a-low failure *findable*.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_prediction_log.py`:
- **Happy path persists before returning.** `record_prediction` returns a row whose
  `prediction_id` is set, and querying `prediction_log` finds exactly that row with the
  right `model_version`, `gate_state`, `baseline_state`, and distribution — i.e. it is in
  the DB by the time the function returns.
- **★ Persistence fails ⇒ NO prediction returned.** With a mock session whose `flush()`
  leaves `prediction_id` unset, `record_prediction` raises `SafetyViolation` (INV-9) and
  returns nothing. With a mock session whose `flush()` **raises**, the error propagates and
  nothing is returned. Write-then-display is enforced, not incidental.
- **`serve_prediction` maps a GuardedPrediction and persists first.** A served refusal and
  a served state both produce a `prediction_log` row (with `guardrail_fired` set for the
  refusal), and the returned `ServedPrediction.prediction_id` matches the persisted row.
- **`serve_prediction` also refuses to return on a failed write** (mock persistence
  failure ⇒ raises, no `ServedPrediction`).

**RED evidence:** `data/predictions.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the tempting refactor is "compute the prediction, show it, log it
in the background / afterwards" — fast, and fatal, because a crash between show and log
loses the record of a prediction she may have acted on. The mocked-failure tests make the
write a precondition of the return, so display-before-log cannot pass.
