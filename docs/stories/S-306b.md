# S-306b — Wire the IOB engine into correction-event capture (discharge DL-020)

**Epic:** 4 (follows S-401) · **Safety story:** feeds ISF · **Status:** In progress
**Requirements:** REQ-013 (completes it) · **Discharges:** DL-020 · **Uses:** S-401

> S-306 captured correction events with `iob_at_start = NULL`, deferring the
> computation to the IOB engine (DL-020). S-401 delivered that engine. This wires
> it in: `iob_at_start` is now **computed** — the confounder that decides whether a
> correction is a *clean* ISF signal (`07` §6: clean iff `iob_at_start < 0.5`).

## Why this was blocked, and is now unblocked
DL-020: `iob_at_start` needs `iob_at()` over `bolus_log` (the Fiasp curve), which
did not exist until **S-401**. Until then the column was NULL and every event was
correctly excluded from ISF derivation (`get_clean_correction_events` treats NULL
as *not clean*). Now the engine exists, so the value can be filled — at capture for
new events, and by a backfill for any captured while it was deferred.

## Design
- **`iob_at_start` at the moment of the correction is the IOB from PRIOR insulin
  only** — not the correction bolus being logged (that is the intervention, not the
  pre-existing on-board insulin). Sourced from injections in `bolus_log` with
  `datetime < event.datetime` (strictly before), so the just-logged correction
  bolus is excluded.
- **`data/repositories.py`**:
  - `boluses_before(session, at)` → `[(datetime, units), …]` for injections
    strictly before `at` (a pure `bolus_log` query, no `features` import).
  - `iob_at_start_at(session, at)` → `features.iob.iob_at(at, boluses_before(…))`.
    The single bridge from the pure engine to the log.
  - `backfill_correction_iob(session)` → for every `CorrectionEvent` with
    `iob_at_start IS NULL`, set it from `iob_at_start_at(session, event.datetime)`;
    returns the count filled. For events captured before S-401 (none in production
    yet — this is pre-ship), so the value is there when ISF derivation (S-502) runs.
- **`api/app.py`** `create_correction_event`: compute `iob_at_start` from prior
  boluses **before** the correction bolus is inserted, and set it on the event.
  The reported time is bound to a local `at` first, so the assignment derives from
  `at` + the log — never from `payload` — keeping the `detect_manual_iob` guard
  green (IOB is derived, not taken from user input).

## Safety note
The `detect_manual_iob` guard forbids `iob… = <user input>`. IOB here is computed
by `iob_at_start_at(session, at)` from `bolus_log`; `at` is a bound reported
timestamp, not the IOB value. The guard stays clean — and the AST test proves no
package assigns IOB from a request/form/payload. A NULL that slips through (e.g. no
engine) is still excluded from the clean set, so the failure mode remains *exclude*,
never *silently admit a confounded event*.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_correction_iob.py`:
- **Capture computes it:** a meal bolus 30 min before, then a correction ⇒
  `event.iob_at_start ≈ units·iob_fraction(30)` from the prior bolus, and **does not**
  include the correction bolus itself.
- **No prior insulin ⇒ `iob_at_start == 0.0`** (a genuinely clean event).
- **Clean-events end-to-end:** a correction with low prior IOB (`< 0.5`) +
  `food_in_window == False` appears in `get_clean_correction_events`; one with high
  prior IOB (`≥ 0.5`) is excluded — the value now drives the `07` §6 filter.
- **Backfill:** an event stored with `iob_at_start = NULL` (pre-engine) ⇒
  `backfill_correction_iob` fills it from prior boluses; returns the count.
- **Guard stays green:** `detect_manual_iob` finds nothing across the tree
  (already in the forbidden suite; this story keeps it clean with the real
  derived site present).

**RED evidence:** `iob_at_start_at` / `boluses_before` / `backfill_correction_iob`
do not exist, and the endpoint leaves `iob_at_start` NULL ⇒ failures before impl.

**Adversarial angle:** the trap is computing `iob_at_start` from **all** boluses
including the correction just logged — which would add a full 1.0·units of the
correction itself, inflating IOB and wrongly excluding a clean event (or worse,
distorting the ISF signal). The "strictly before" boundary and the capture-order
test pin it to pre-existing insulin only.
