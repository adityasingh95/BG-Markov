# S-1024 — Local deployment, and the database says what it is

**Epic:** 11 · **Safety story:** **Yes — provenance** · **Status:** 🔧 In progress ·
**Requirements:** REQ-056, `06 §7` · **Records:** DL-062

> The operator is about to run this on his laptop and click through it by hand. To do that
> usefully he needs demo data. **On screen, synthetic data is indistinguishable from hers.**

## Story
The app runs locally in one command, and **a database full of synthetic data says so on
every screen it renders.**

---

## Written safety argument

### Why a demo banner is a safety feature and not decoration

`scripts/seed_demo_db.py` produces 658 meals, 1034 boluses, 29 hypo rescues and a fitted
model. Every screen renders it exactly as it renders real capture: the adherence dashboard
says *"413 / 150 valid meals"*, the calculator subtracts a real-looking IOB, the shadow
report scores a real-looking model.

The failure this enables is not a crash. It is **believing a number**. An operator who
checks the shadow report on a seeded database and sees a plausible hypo recall has learned
nothing about her, and nothing on the page tells him so. That is the project's stated
worst case — *"a model that looks good on retrospective data, gets trusted, and is quietly
wrong about a low"* — reached by a different road.

### Why the marker lives in the database, not in the environment

An environment variable can be forgotten, inherited, or left set from the previous run, and
the mistake is silent in both directions. **The provenance belongs to the data**, so it is
written into the database by whatever created it and read back by whatever renders it. Move
the file, reopen it a month later, hand it to someone else — it still says what it is.

This is the same principle as `shadow_days` being a **derived count rather than a stored
boolean** (S-1007) and gates being evaluated live (ADR-7): the answer is re-derived from
the thing itself, so it cannot drift from reality.

### Why one banner, in one place

Two `Jinja2Templates` instances already exist — `api/app.py` and `api/bolus.py`. A context
added to one and not the other is exactly the shape of every gap this epic found. So they
are consolidated into a single `api/templating.py`, the banner is a **context processor** on
that one object, and a test enumerates **every** HTML route and asserts the banner on all of
them. Per-template opt-in would be forgotten on the next page anyone adds.

## Acceptance criteria

1. `./scripts/dev.sh setup` builds a venv, installs, and creates the schema **via Alembic**.
2. `./scripts/dev.sh serve` runs the app on `127.0.0.1:8000` (`06 §7` — never off localhost).
3. `./scripts/dev.sh demo` creates a **seeded, demo-marked** database and serves it.
4. `./scripts/dev.sh reset` deletes the local database, with a confirmation.
5. A demo-marked database renders a banner on **every** HTML page.
6. An unmarked database renders **no** banner on any page.
7. `seed_demo_db` **always** marks. A seeder that can produce an unmarked demo database is
   the whole defect.
8. `docs/RUNBOOK.md`: how to run it, what to click, and **what is known not to work**.

## TDD strategy (SDET first — written and seen to fail)

`tests/unit/test_provenance.py` — mark, read back, idempotent re-mark, unmarked ⇒ `False`.

`tests/safety/test_demo_banner.py`
- **★ Every HTML GET route** — enumerated from the app, not hand-listed — shows the banner
  on a demo-marked database. A hand-listed set is a list someone forgets to extend.
- **★ No page shows it on an unmarked database.** A banner that is always on is a banner
  nobody reads, and it would then be present on her real records.
- **★ There is exactly ONE `Jinja2Templates` instance under `api/`.** The second instance is
  how the first gap gets in.
- **★ `seed_demo_db.seed()` produces a marked database.** The seeder is the only thing that
  makes synthetic data, so it is the only place the mark can be forgotten.

**Adversarial angle.** (a) **Reading the flag from an env var** — silently wrong in both
directions. (b) Adding the banner to `index.html` only, which is the page you happen to be
looking at. (c) A banner that renders as an empty string when unmarked but still occupies
layout, so the "no banner" test passes on a page that has one.
