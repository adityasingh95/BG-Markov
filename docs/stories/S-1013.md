# S-1013 — Basal capture (daily Tresiba)

**Epic:** 10 · **Safety story:** No — but it closes a **hard blocker** · **Status:** ✅ Done (2026-07-18) · **Requirements:** REQ-007 · **Records:** **DL-046** (the gap and the traceability
correction) · **Blocks:** S-1009 · **Rollback baseline:** `7a7c3bf`

> `basal_log` has existed as a table since S-201 and `features/basal.py` has computed
> `effective_basal` from it since S-402. **Nothing in the system can write a basal dose.**
> A grep for `BasalLog` across the tree returns exactly one hit: its own definition.

## Story
She records the daily Tresiba — how much, and **when she actually took it** — so
`effective_basal` can be computed from real data.

## Why this blocks the refit

`effective_basal` is a model feature (REQ-021). Without recorded doses there is nothing to
smooth, so **the model cannot be fitted on real data at all**. S-1009 would have hit this
halfway through, with the assembler already written.

**Why it went unnoticed** (DL-046): every consumer so far either tested the EWMA in
isolation (S-402, pure functions over a list) or **fabricated the value in memory** —
`scripts/demo_end_to_end.py` and the E2E cycle both do. Nothing had yet asked the database
for it. *A feature nobody has sourced end-to-end is a feature nobody has checked exists.*

## Design

### `data/recording.py::record_basal(session, *, date, units, time_taken, clock)`
- **`time_taken` is REPORTED** — when she injected — and `logged_at` comes from the
  injectable clock (ADR-8). Tresiba is taken at roughly the same time daily and logged
  whenever she is next at the laptop; conflating the two would corrupt the EWMA's time
  axis, which is the whole basis of the 25-hour half-life.
- **One row per date** (`date` is the primary key). Re-recording an existing date is a
  **correction, not a duplicate**: the row is updated and the change written to
  `audit_log` (old → new), like promotion. Two rows for one day would double-count the
  dose in the smoothing.
- `units > 0`.

### `data/repositories.py::basal_doses(session)`
Returns `[(datetime, units), …]` — the reported `date` + `time_taken` combined into the
timestamp the EWMA needs — ordered. **The only bridge** from `basal_log` to
`features.basal`.

### `POST /api/basal` + `GET /basal`
A two-field form: units, and the reported time. Numeric keypad, per `05b §2`.

## ★ The forbidden pattern this story sits next to

*"Today's basal dose as a feature"* is explicitly forbidden: Tresiba has ~42 h action and a
3–4 day steady state, so **today's dose is not today's effect**. This story creates the
first real source of `basal_log.units`, which is exactly the value a future contributor
would reach for. The guard already exists (S-105 lineage); the tests here assert that the
raw daily figure never reaches the model, and that only the EWMA does.

## TDD strategy (SDET first — written and seen to fail)
`tests/integration/test_basal_capture.py`:
- **★ `time_taken` is reported and `logged_at` is the clock** — they differ, and the
  reported value is never overwritten by the system clock (ADR-8).
- **★ Re-recording a date corrects rather than duplicates**, and the correction is
  **audited** old → new. Two rows for one day would double-count in the EWMA.
- `units <= 0` is refused.
- **★ `basal_doses` → `effective_basal` matches the S-402 EWMA** on the same input — the
  bridge from the DB is the thing this story adds, so it is what gets asserted.
- **★ A step change is smoothed, not stepped:** 24 U → 30 U shows a value strictly between
  the two the next day, and near 30 after five. The whole point of the feature.
- The form posts and the row appears; numeric inputs carry `inputmode="numeric"`.

`tests/forbidden/` (extend):
- **★ No production module reads `BasalLog.units` as a model feature** — only via
  `basal_doses` → `effective_basal`.

**RED evidence:** `record_basal` does not exist; `POST /api/basal` 404s.

**Adversarial angle.** Two. (a) `datetime.now()` for `time_taken`, because she is usually
logging it right after taking it — *usually* is what makes it dangerous. (b) Using
`units` directly as a feature, which is one line, reads sensibly, and is wrong for a
42-hour insulin.

### ★ Two process hazards, recorded because they are the S-1005 lesson in a new costume
Verifying the plants went wrong twice before it went right:

1. **`git checkout` cannot restore an untracked file.** `data/basal.py` was new, so two
   plants accumulated in it silently — and the *next* plant's result was measured against a
   doubly-corrupted file. The output looked like more guards firing; it was one broken file.
2. **`git checkout` on a tracked file reverts *all* uncommitted work in it.** Reverting the
   third plant silently deleted `basal_doses` — the accessor this story adds — and turned
   the suite red for a reason that had nothing to do with the plant.

A third, smaller one: the third plant initially broke **syntax** rather than behaviour, so
the suite reported a *collection error*. That is not evidence an assertion bites; it is
evidence the file no longer parses.

**The rule that fixes all three: commit the implementation before planting**, verify the
plant applied *and* that the file still parses, and revert to a known commit. The
adversarial pass was re-run cleanly on top of the GREEN commit.

The recurring shape is worth naming: **a plant is only evidence if you know exactly what
state the tree was in.** S-1005 caught the "the plant did nothing" version; this caught the
"the plant did too much" and "the plant broke the wrong thing" versions.

### Deviations from the design above
One, minor. The story put `basal_doses` in `data/repositories.py` and `record_basal` in
`data/basal.py`; the first draft tried to re-export the accessor through `repositories` with
an `__all__` built from `dir()`. That was a hack — it would have exported every import in the
module. The accessor now simply *lives* where the other accessors live.

### Still open
The **24-hour edit window** (`04 §10` — *"edits are permitted within 24 h and always
audited"*) is **not enforced** on basal corrections. Corrections are audited; they are not
time-limited. Enforcing it here was not in the AC, and inventing the limit would be the kind
of unsanctioned tightening BA is meant to flag. Raised rather than silently applied or
silently skipped.
