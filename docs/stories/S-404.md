# S-404 — Feature pipeline (closes EPIC 4)

**Epic:** 4 (Derived Features) — **the leakage-critical story** · **Safety story:**
No (but leakage is "the one class of bug that makes a model look brilliant and be
useless") · **Status:** In progress · **Requirements:** REQ (07 §5), 09 §7

> Leakage is the failure that looks like success. A random split leaks day-level
> information (basal is constant within a day, days autocorrelate) and makes the
> model look brilliant while being useless — and worse, quietly wrong about a low.
> Every guard here exists to make that loud: temporal-only folds, scaler fit on
> train folds, and `post_bg`/`elapsed_min` never in the feature vector.

## Story
Assemble the model's feature matrix from the meal record plus the EPIC-4 derived
features (IOB, effective basal, exercise), with `pre_bg` **continuous**,
`macro_confidence/100` as **`sample_weight`**, standardisation **fit on train folds
only**, and a **forward-chaining temporal** cross-validation splitter (never
random).

## Requirement source
- **07 §5** — the feature vector (below); continuous features standardised via
  `StandardScaler` inside a `Pipeline`, **fit on training folds only**;
  `macro_confidence/100` as `sample_weight`.
- **07 §8 / 09 §7** — **forward-chaining temporal CV, NEVER random**; no `date` in
  both train and test in any fold; `max(train.datetime) < min(test.datetime)`.
- **CLAUDE.md forbidden patterns** — "Binning `pre_bg` as an input", "Random
  train/test split", scaler leakage.

## The feature vector (07 §5) — targets excluded
`pre_bg` (continuous), `carbs_g`, `net_carbs_g`, `protein_g`, `fat_g`, `fiber_g`,
`meal_bolus_units`, `correction_bolus_units`, `bolus_offset_min` (signed),
`iob_at_meal` (derived), `effective_basal` (EWMA), `minutes_since_last_bolus`,
`meal_type_lunch`, `meal_type_dinner` (breakfast/snack = baseline), `ex_light`,
`ex_intense`, `ex_duration_min`, `ex_offset_min`, `ex_light_x_duration`,
`ex_intense_x_duration`, `pre_ex_light`, `pre_ex_intense`, `pre_ex_duration_min`.
**`post_bg` and `elapsed_min` are the OUTCOME — they never appear here.**

## Design
- **`features/pipeline.py`**:
  - `FEATURE_NAMES` — the ordered vector above (target columns absent by
    construction).
  - `CONTINUOUS_FEATURES` — the numeric subset to standardise (indicators are
    left unscaled).
  - `feature_vector(meal, *, iob_at_meal, effective_basal,
    minutes_since_last_bolus)` — a `dict[str, float]` over exactly `FEATURE_NAMES`.
    `pre_bg` is continuous; exercise via S-403's `encode_exercise`; the three
    derived quantities are supplied by the caller (from IOB / basal engines and
    `bolus_log`).
  - `sample_weight(meal)` = `macro_confidence / 100`.
  - `make_scaler()` → a `sklearn` `StandardScaler` to be fit **inside** CV on a
    train fold.
- **`features/cv.py`**:
  - `forward_chaining_folds(dates, n_splits)` → `[(train_idx, test_idx), …]`,
    partitioning **unique days** into ordered contiguous blocks so every fold has
    `max(train day) < min(test day)` and **no day appears in both**.
- Pure/deterministic; no clock, no DB (the caller supplies rows + derived values).

## Dependency decision
`StandardScaler` (and later the modelling stack) is `scikit-learn`, which was not
yet a dependency. Added **pinned** `scikit-learn==1.9.0` (per S-101's pinned-deps
AC) with a `mypy` `ignore_missing_imports` override (its stubs are incomplete, like
`pandas`/`statsmodels`). 1.9.0 is ≥1.7, where `LogisticRegression(multi_class=…)`
is removed — irrelevant here (the model is `statsmodels` `OrderedModel`, and the
forbidden-pattern guard already bans `multi_class`). Recorded in the decision log.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_pipeline.py`:
- `feature_vector` keys == `FEATURE_NAMES`; `pre_bg` is the raw continuous value;
  a lunch meal sets `meal_type_lunch=1, meal_type_dinner=0`; exercise features
  match `encode_exercise`; the supplied derived values pass through.
- `sample_weight` == `macro_confidence/100` (e.g. 95 ⇒ 0.95).

`tests/leakage/test_leakage.py` (09 §7 — runs every commit):
- **No target leakage:** `post_bg` and `elapsed_min` are **not** in
  `FEATURE_NAMES` (nor any `feature_vector` key).
- **`pre_bg` continuous:** `pre_bg` is in `FEATURE_NAMES` as a scalar; there is no
  binned `pre_bg_*` input feature.
- **Temporal ordering:** for every fold from `forward_chaining_folds`,
  `max(train.datetime) < min(test.datetime)` and train/test day-sets are disjoint.
- **★ Scaler fit on train folds only:** a `StandardScaler` fit on a train fold has
  **different** `mean_` from one fit on the full set — proving the split is
  respected and test statistics never leak into scaling.

**RED evidence:** `features/pipeline.py` and `features/cv.py` do not exist ⇒ import
errors before impl.

**Adversarial angle:** the two classic leaks — (1) fitting the scaler on all rows
"for convenience" (the scaler-stats test catches it), and (2) a random `KFold`
split that puts the same day in train and test (the temporal-ordering + disjoint-day
test catches it). Either makes hypo recall look great in CV and fail in life.
