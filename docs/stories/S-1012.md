> `gate1_status()` implemented four. `calibration acceptable (held-out)` was enforced nowhere
> (DL-041 — which also corrects the S-1007 note that wrongly claimed code and spec agreed).

> was **answered 2026-07-18 (DL-042)**.

## Story
Gate 1 additionally requires the model's **hypo probabilities to be honest** — when it says
30%, roughly 30% of those meals must actually end low — judged by the coarse, asymmetric rule
approved in DL-042.

## What the check is actually asking

Not *"is the model good?"* — that is hypo recall vs the baseline, a different condition. This
asks only: **when it puts a number on the risk, is the number true?**

A model can rank meals correctly (the risky ones above the safe ones) and still be badly wrong
about the magnitudes — saying 30% when the truth is 60%. For someone who can feel a low coming,
that is an annoyance she corrects for herself. **For her, the number is the warning.** A model
that consistently understates risk tells her "probably fine" on meals that are not.

## Design

### `models/metrics.py` — the computation
Lives beside `reliability_curve`, which already produces the raw evidence. Named constants,
each traced to DL-042 in its comment so tuning one is visibly *changing an approved decision*:

| Constant | Value | Meaning |
|---|---|---|
| `HYPO_CALIB_BUCKET_EDGES` | `(0.20, 0.50)` | Three buckets, not ten |
| `HYPO_CALIB_MIN_BUCKET_N` | `20` | Below this a bucket is noise, not evidence |
| `HYPO_CALIB_MAX_UNDERSTATEMENT` | `0.10` | **The dangerous direction** |
| `HYPO_CALIB_MAX_OVERSTATEMENT` | `0.20` | A wasted fingerstick, not a harm |

```python
hypo_calibration(hypo_score, is_hypo) -> CalibrationVerdict
```
- Operates on **`P(state ≤ 2)` only** — the number a warning is made of. Calibrating all five
  class probabilities would dilute the one that matters into four that do not.
- **Signed gap = `observed − claimed`.** Positive means the model **understated** the risk.
  The sign is the whole point; an absolute value would erase the asymmetry.
- Buckets below `HYPO_CALIB_MIN_BUCKET_N` are **reported but not judged** — visible on the
  dashboard as *"too few to judge"*, never silently dropped.
- **Fails closed:** no bucket reaches the floor ⇒ `is_acceptable = False`.
- `CalibrationVerdict` carries a plain-language `reason` so S-1001 can say *why*, not just no.

### `prescribe/gates.py`
- `gate1_status(..., calibration_ok: bool)` — **required, not defaulted.** Third time this
  reasoning applies (`is_promoted` S-1006, `shadow_days` S-1007): a default is a decision made
  once, by this function, for every future call site, and it lets a caller omit the question
  and still compile.
- `Gate1Status` gains `calibration_ok`, so S-1001 renders **five** conditions.
- **`gates.py` stays DB-free and model-free.** It still imports only `core.safety`. It takes a
  `bool` the caller computes fresh — which is what makes ADR-7's "never cached" structural.

## Written safety argument [SAFETY]

**Why a gate condition and not just a dashboard number.** A number on a screen is advice. A
gate condition is a refusal. The spec has always had this as a condition; only its threshold was
missing. Leaving it as an unenforced display would mean an operator could promote a model whose
percentages were plainly dishonest, having read past the row that said so.

**Why coarse is the safe choice, not the lazy one.** At gate time there are ~150 valid meals
with perhaps 15–20 lows. The conventional ten-bin reliability curve spreads those across ten
buckets — three or four events each — and returns a confident-looking verdict built on almost
nothing. **A rule satisfiable only by luck is not a safety check.** Three buckets with a
minimum size is the most this much data can honestly support, and a check that admits what it
cannot see is worth more than one that pretends.

**Why asymmetric.** This is the asymmetry the whole system already carries — hypo-weighted
training (S-601), rescued lows retained (INV-7), the 70→80 warning edge (DL-043), refusal
preferred over a guess (S-801). Overstating risk spends a fingerstick. Understating it spends
the only warning she gets. A symmetric rule prices those the same; they are not the same.

**Why "cannot judge" ⇒ "not acceptable".** The tempting reading of an empty result is *"no
evidence of a problem."* It is not — it is *no evidence*. Every ambiguity resolves toward the
gate staying shut, as with `shadow_days` clamping to 0 and `get_promoted_artifact` returning
`None`.

**What this does not do.** It does not open Gate 1 and it does not say the model is good. It is
the fifth of five. All must hold.

## TDD strategy (SDET first — written and seen to fail)
`tests/unit/test_calibration.py`:
- **★ The asymmetry, both directions at the same magnitude.** A bucket claiming 0.20 where
  0.35 actually happened (understates by 0.15) ⇒ **NOT acceptable**. A bucket claiming 0.50
  where 0.35 happened (overstates by 0.15) ⇒ **acceptable**. Same 0.15 gap, opposite verdicts.
  If a refactor ever takes `abs()`, this is the test that dies.
- Boundary: understatement of exactly 0.10 passes, 0.101 fails; overstatement 0.20 passes,
  0.201 fails.
- **★ 19 predictions in a bucket ⇒ not judged; 20 ⇒ judged.**
- **★ Fails closed** — every bucket under the floor ⇒ `is_acceptable is False`, and the reason
  says *cannot judge*, not *fine*.
- No predictions at all ⇒ not acceptable.
- A bucket below the floor is **still reported** (dashboard must show it), just not judged.
- A well-calibrated set across all three buckets ⇒ acceptable.
- Buckets partition `[0, 1]` exactly at 0.20 / 0.50 — a score of exactly 0.20 lands in the
  middle bucket, exactly 0.50 in the middle bucket, no score falls through.

`tests/safety/test_gates.py`:
- **★ Four conditions ✓ and calibration ✗ ⇒ CLOSED.** The others are asserted true so the test
  can only pass for the calibration reason.
- **★ `calibration_ok` is required** — omitting it raises `TypeError`.
- Honest percentages never substitute for the other four (200 meals, promoted, 500 shadow days,
  recall ≤ baseline, calibration ✓ ⇒ still closed).
- No env var flips it.

**RED evidence:** `hypo_calibration` does not exist; `gate1_status` takes five arguments.

**Adversarial angle.** Three temptations. (a) `abs(gap)` — reads cleaner, silently deletes the
asymmetry, and nothing in a green build reveals it. (b) Treating an unjudgeable bucket as a pass
— "no evidence of a problem" is not "no problem". (c) Lowering `HYPO_CALIB_MIN_BUCKET_N` when
real data fails to reach 20. **The rule for that case is written in DL-042: do not lower the
floor — conclude there is not yet enough evidence and leave the gate shut.**

## Outcome (BA, 2026-07-18)

**Done.** `models/metrics.py::hypo_calibration` + `gate1_status(..., calibration_ok)`.
518 tests green, 99.66% coverage, `ruff` and `mypy --strict` clean. Commits: `277193b` (BA)
→ `4a10b4e` (SDET RED) → `93ac6df` (Dev GREEN). Records: DL-041 (the gap), **DL-042** (the
rule), OQ-9 (resolved).

**Gate 1 now implements all five conditions `03 §3` lists.** The divergence DL-041 found is
closed, and `test_all_five_conditions_are_required_together` is the test that would have
caught it — each condition, held false alone, shuts the gate.

**One real defect found by the SDET boundary test, and it was in the arithmetic, not the
design.** `0.30 − 0.20` evaluates to `0.10000000000000003` in floating point, so a bare
`<=` failed DL-042 **at its own stated boundary** — the approved rule was literally
unimplementable as written. Fixed with a documented `_FP_SLACK = 1e-9`: representation
error only, ~10 orders of magnitude below anything measurable on a probability, and unable
to move a verdict that was not already exactly at the edge. The 0.101 case still fails.
Worth recording because a boundary that silently rounds the *wrong* way is precisely the
kind of thing that never shows up in a green build.

**Guards seen to fire, then reverted.** Four plants:
- **`abs(gap)`** — the obvious simplification, deletes the asymmetry ⇒ 3 tests fail.
- **"cannot judge" returned as acceptable** — the tempting reading of an empty result
  ⇒ 3 tests fail.
- **`HYPO_CALIB_MIN_BUCKET_N` lowered 20 → 5** — the exact move DL-042 forbids when real
  data does not reach the floor ⇒ 4 tests fail.
- **`calibration_ok` dropped from the conjunction** ⇒ 3 tests fail.

**Deviations from the design above:** none, beyond `_FP_SLACK`.

**Found while running the demo, not while reading it.** On the demo's synthetic data the
check correctly fails a badly over-confident model: in the band where it says a low is
likely it claimed **88%** on average and **36%** actually went low. That is the failure
mode this condition exists for, caught on the first real run — and it is a useful reminder
that a model can look reasonable on recall and still be wildly dishonest about magnitude.

**What it does not do.** Gate 1 is still closed. Five conditions; this is one of them.
