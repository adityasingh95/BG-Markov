# S-203 [SAFETY] — ★ Validity engine + INV-7

**Epic:** 2 (Data Layer) · **Safety story:** Yes · **Status:** In progress

## Story
Compute record validity per `04-data-model.md §5` / `03-state-model.md §2`, and
expose the two accessors the model layer depends on: `get_training_set()` (valid
rows only) and `get_hypo_events()` (rescued rows **retained** as hypo events).
This is the first story that **wires a safety invariant** — INV-7 — into a
feature: the training-set accessor calls `core.safety.inv7_rescued_excluded_and_
retained`, so a training set that violated INV-7 cannot be returned; it raises.

## Requirement sources
- **REQ-022** — records validated per `04 §5`; `elapsed_min` stored even when
  invalid (the column already exists from S-201).
- **REQ-023 / INV-7** — hypo-rescued meals excluded from outcome regression but
  **retained as hypo events**.

## The six exclusion rules (`04 §5`)
| Reason | Condition |
|---|---|
| `missing_outcome` | `post_bg` is null |
| `outside_window` | `elapsed_min` outside **[105, 135]** |
| `rescued` | `hypo_treatment = true` (→ INV-7) |
| `uncontrolled_intake` | `snack_during_window = true` |
| `iob_cob_contamination` | previous meal **< 3 h** prior |
| `low_confidence` | `macro_confidence < 50` |

**All applicable reasons are recorded, not just the first.** `is_valid` is true
iff the reason list is empty.

## Acceptance criteria (backlog)
- [ ] All six rules with correct reasons; **all applicable reasons recorded**.
- [ ] `elapsed_min` stored even when invalid (S-201; unchanged).
- [ ] `get_training_set()` and `get_hypo_events()` both exist.

## Design
- **`core/validity.py`** (pure, core-covered): `exclusion_reasons(...)` returns
  every applicable reason in canonical order; constants `VALID_ELAPSED_MIN=105`,
  `VALID_ELAPSED_MAX=135`, `MIN_INTERMEAL_MIN=180`, `MIN_MACRO_CONFIDENCE=50`,
  `HYPO_POST_BG_MAX=80` (State ≤2). `is_hypo_outcome(post_bg)` = measured low.
- **`data/repositories.py`**:
  - `get_training_set(session)` — valid meals only (empty reason list),
    then **calls `inv7_...`** with (training ids, hypo ids, rescued ids) before
    returning. Cannot return an INV-7-violating set.
  - `get_hypo_events(session)` — `hypo_treatment` **or** a measured low
    (`post_bg < 80`). Rescued rows are retained here even if their post-rescue
    `post_bg` looks normal — that is the whole point.
  - `annotate_validity(meal, prev_meal_datetime)` — persists `is_valid` +
    `exclusion_reasons` at write time (`04 §5`).

## Why INV-7 is wired here, not just checked [SAFETY]
The natural refactor — *"invalid rows get dropped from the training set"* —
silently deletes every low she ever had, and the model is then trained on a
world where she never goes low. INV-7 lives in `core/safety.py`; S-203 makes the
**training-set accessor** call it, so the deletion cannot happen quietly: if a
rescued id ever appears in the training set, or is missing from the hypo events,
`get_training_set()` raises `SafetyViolation`. The accessor is the choke point,
and the invariant guards it.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_validity.py`:
- **Window boundaries:** `elapsed_min` 105 ⇒ valid; 104 ⇒ `outside_window`;
  135 ⇒ valid; 136 ⇒ `outside_window`.
- Each rule fires on its trigger; **multiple triggers ⇒ multiple reasons** in one
  list (e.g. rescued + low_confidence + outside_window together).
- `is_valid` iff no reasons.

`tests/integration/test_repositories.py`:
- `get_training_set` excludes invalid rows; `get_hypo_events` includes a rescued
  meal whose `post_bg` is normal.
- **★ REGRESSION GUARD: 100 meals, 20 rescued ⇒ `get_training_set` excludes all
  20; `get_hypo_events()` returns exactly 20.**
- **INV-7 wiring bites:** if the exclusion logic is subverted so a rescued meal
  is treated as valid (the exact forbidden refactor), `get_training_set` raises
  `SafetyViolation`.

**RED evidence:** `core.validity` / `data.repositories` absent ⇒ import error.

**Adversarial angle:** the regression guard *will* look redundant next to the
unit rules. It is not — it is the one test that catches a future refactor
deleting her lows wholesale. **Do not delete it.**
