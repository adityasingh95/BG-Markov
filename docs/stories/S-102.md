# S-102 — Accessible base layout

**Epic:** 1 (Foundation) · **Safety story:** No (but accessibility here *is*
patient-safety: she may be logging while cognitively impaired by a low) ·
**Status:** Done

## Story
Stand up the shared UI shell — the base Jinja2 layout, the vendored Pico.css +
design tokens, and the accessible input primitives — that every later logging
and readout story is built on. This story ships no clinical behaviour and no
model output. It ships the **accessibility floor** that `05b §2` declares
non-negotiable, and it wires the browser-level a11y checks (axe, 200 % zoom)
into the test suite so a future template change that regresses accessibility
turns the build red instead of shipping.

Stack per `06 §3` / `05b`: **Jinja2 + HTMX + Pico.css, no build step, no React.**
FastAPI serves the templates and static assets from `127.0.0.1`.

## Requirement source
No numbered `REQ-nnn` covers accessibility. The backlog cites the requirement
directly as **`05b §2` (Accessibility — Non-Negotiable)**. Traceability records
the source as `05b §2` rather than a REQ id.

## Acceptance criteria (from backlog + `05b §2`)
- [x] Base font **≥ 18px**. — `:root{font-size:18px}`; `test_base_font_at_least_18px`.
- [x] Touch targets **≥ 48 × 48 px** (buttons and primary numeric inputs). —
      `test_touch_targets_at_least_48px`.
- [x] `inputmode="numeric"` on **every** BG / dose field. — enforced by the
      `numeric_field` macro; `test_every_bg_dose_field_is_inputmode_numeric`.
- [x] **No colour-only signalling** — icon + text carry the meaning, colour only
      reinforces it. `test_warning_not_signalled_by_colour_alone`.
- [x] **No dropdowns** (`<select>`) for dish selection — search + recents.
      `test_no_select_for_dish_selection`.
- [x] `axe` passes (no violations) on the base layout. `test_axe_no_violations`.
- [x] Usable at **200 % zoom** — no horizontal page overflow.
      `test_no_horizontal_overflow_at_200pct_zoom`.

## TDD strategy (SDET, written first — seen to fail)
Floor from backlog: *axe passes; usable at 200 % zoom; every numeric field
asserts `inputmode`.* Expanded to a browser-driven suite (`tests/a11y/`,
Playwright + axe-core against the live FastAPI app, driving real Chromium so
computed styles and zoom are genuine, not asserted from source text):

1. `test_axe_no_violations` — axe-core finds **zero** violations on the base
   layout. The core a11y audit: labels, landmarks, contrast, lang, roles.
2. `test_every_bg_dose_field_is_inputmode_numeric` — every field marked as a
   numeric BG/dose field renders `inputmode="numeric"`. A dose/BG field without
   it fails.
3. `test_base_font_at_least_18px` — computed `font-size` on `<body>` ≥ 18px.
4. `test_touch_targets_at_least_48px` — every button and primary numeric input
   has a computed box ≥ 48 × 48 px.
5. `test_no_select_for_dish_selection` — the dish picker contains **no
   `<select>`**; it is a search box + recents buttons.
6. `test_no_horizontal_overflow_at_200pct_zoom` — at an effective 200 % zoom the
   document does not overflow horizontally (`scrollWidth ≤ clientWidth`).
7. `test_warning_not_signalled_by_colour_alone` — a warning/risk element carries
   a **text or icon** cue, not only a colour class. Guards `05b §2` "colour is
   never the sole signal."

**RED evidence:** with no `api/` app yet, the live-server fixture cannot start /
the page cannot be fetched, so every a11y test errors/fails. Committed as
`test(S-102): RED …`.

**Adversarial angle:** the axe + zoom tests look like heavyweight scaffolding for
a one-person tool. They are not decorative. She logs *at BG 55*. A template
refactor that drops a label, inverts contrast, or introduces a `<select>` for
dishes is exactly the kind of silent regression these tests exist to catch.

## Test infrastructure introduced
- Pinned dev deps: `playwright`, `axe-playwright-python`, `httpx` (for the live
  server / driving). See `pyproject.toml`.
- Chromium: this session uses the pre-installed browser at
  `$PLAYWRIGHT_BROWSERS_PATH/chromium`; CI installs it via
  `playwright install --with-deps chromium`. The browser-resolution helper
  prefers the pre-installed path and falls back to Playwright's own.
- `a11y` pytest marker registered.
