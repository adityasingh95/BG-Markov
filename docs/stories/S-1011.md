# S-1011 [SAFETY] — Retire Gate 2 / INV-1 (ICR de-gated)

**Epic:** 10 (Integration, UI & End-to-End Validation) · **Safety story:** Yes — this *removes*
a safety invariant · **Status:** In progress · **Requirements:** REQ-041 (retired), **INV-1
(retired)** · **Decision:** DL-035 (planned 2026-07-18), operator go given 2026-07-18 ·
**Rollback baseline:** `7a7c3bf` (`v1.0.0-epic9`)

> **This story lowers a safety floor on purpose.** Every other `[SAFETY]` story in this build
> added a guard. This one removes one, at the operator's explicit and repeated direction. The
> written argument below is therefore not a formality — it is the record of what protection is
> being given up, what remains, and why the remainder is judged sufficient.

## Story
Remove the clinician-confirmed-ICR **gate** (Gate 2 / INV-1). ICR, ISF, and target become
ordinary values read from the versioned `patient_profile`. The bolus calculator no longer
hard-disables itself; it simply requires a usable ICR to do arithmetic with.

**The ICR value does not change** (9 g/U, DL-032). Only its *gate status* is removed.

## Requirement source
- **DL-035** — the operator's decision to de-gate ICR, with the chosen fallback: **keep a basic
  input check**, raising an ordinary `ValueError` (explicitly **not** `SafetyViolation` /
  `GateNotPassed`) on a missing or non-positive ICR.
- **`07 §11`** — the clinical formula itself is unchanged: `carb_dose = carbs_g/icr;
  correction = (current_bg − target_bg)/isf; dose = max(0, carb + correction − iob)`.
- **CLAUDE.md** — INV-1 is retired, **not renumbered**. INV-2…INV-9 keep their numbers.

## Design

### Removed
| Where | What |
|---|---|
| `core/safety.py` | `inv1_prescriptive_requires_gate2` |
| `prescribe/gates.py` | `Gate2Status`, `gate2_status`, `require_gate2` |
| `prescribe/bolus.py` | the `require_gate2(gate2_status(icr=icr))` call |

### Changed
- **`prescribe/bolus.py`** — `icr: float | None` → **`icr: float`** (required, not nullable).
  A new guard raises `ValueError` when `icr` is missing or `≤ 0`, *before* any arithmetic.
  The `cast` used for gate-narrowing is no longer needed.
- **`core/config.py`** — `prescriptive_enabled` → **`icr_present`**. With no gate behind it, a
  property named *"enabled"* that enables nothing is actively misleading in a safety system: a
  future reader could take `prescriptive_enabled is False` as "the dose path is safely off",
  which would be false. Renaming makes it what it is — a config-completeness flag.

### Kept — deliberately, and these are the argument
- **`GateNotPassed`** stays in `core/safety.py`. Gate 1 / INV-2 still raises it.
- **Gate 1 / INV-2** — entirely untouched. Patient visibility is a *different* mechanism and
  remains gated.
- **INV-3** — dose never negative; over-cap is **flagged as implausible input**, never silently
  clipped.
- **INV-4** — no bolus below BG 80.
- **No ML in the dose path** — unchanged, still guarded by the AST import test.
- **Versioned, append-only `patient_profile`** — the ICR remains auditable and updatable.

## Written safety argument [SAFETY]

**What is being given up.** Before this change, a missing or unconfirmed ICR made the
prescriptive module *structurally unreachable*: `require_gate2` raised before any arithmetic,
and no flag, fixture, env var, or parameter could open it. CLAUDE.md called this "the most
dangerous code in the system … the gate *is* the feature." After this change there is **no
confirmation checkpoint**: the calculator will compute a dose from whatever ICR is present in
the profile. If a wrong-but-positive ICR is ever written to the profile, the calculator will
use it and produce a plausible-looking wrong dose. That risk is real and is accepted by the
operator (DL-035).

**Why the remaining protections are judged sufficient.**
1. **The formula cannot run on nothing.** ICR is a divisor. The `ValueError` guard fires on
   `None`, `0`, and negatives *before* any arithmetic, so the failure mode "divide by null /
   silently produce `inf` or a negative dose" is closed. This is arithmetic correctness, which
   survives the de-gating intact.
2. **The dose is still bounded on both sides.** INV-3 floors at 0 and caps at
   `MAX_BOLUS_U` (15 U), and a cap event is **flagged as an implausible input** rather than
   handed back as a confident 15 U. A wrong ICR large enough to matter drives the dose over the
   cap and is therefore *surfaced*, not silently dosed.
3. **The system still refuses to dose a low.** INV-4 raises below BG 80 before the formula runs.
   The single most dangerous action — adding insulin to someone already low, who cannot feel it
   — remains structurally blocked.
4. **No model can reach the needle.** The dose path imports nothing from `models/`; the AST test
   still enforces it. Everything the rest of this build guards against — leakage, confounding,
   a mis-fit model — remains unable to influence a dose.
5. **She still checks the arithmetic.** The full working is displayed and framed as *a
   suggestion for review*. A wrong ICR shows up in the displayed division, in front of someone
   who has done this maths by hand for 30 years.
6. **The value is auditable.** ICR lives in the versioned, append-only `patient_profile`; a
   change creates a new row and never overwrites. A wrong value is traceable to when and by whom
   it was introduced.
7. **Patient safety is not this gate's job.** Gate 1 / INV-2 — the invariant that decides
   whether she ever *sees* model output — is untouched and still closed.

**Residual risk, stated plainly.** The failure this no longer prevents is: *a plausible but
clinically wrong ICR is written to the profile and the calculator dutifully uses it.* Mitigated
by (2) the cap-and-flag, (5) her own review of the shown arithmetic, and (6) the audit trail —
but **not eliminated**. Recorded here so the trade is visible rather than discovered later.

## TDD strategy (SDET first — tests updated to the new contract before Dev edits code)
`tests/safety/test_bolus.py`:
- **Removed:** the INV-1 `GateNotPassed` and no-bypass/env-var cases.
- **★ Added:** `icr=None` ⇒ **`ValueError`**; `icr=0` and `icr=-9` ⇒ `ValueError`.
- **★ Added — the discrimination test:** the raised error is **not** a `SafetyViolation` and
  **not** a `GateNotPassed`. This is the assertion that pins the *kind* of the new behaviour;
  without it a future refactor could quietly reinstate a gate (or downgrade an invariant) and
  still pass.
- **Kept unchanged:** INV-4 (BG 79 refuses / 80 computes), INV-3 typo cap **and** flag, INV-3
  negative ⇒ 0.0, the 5 golden hand-computed doses, non-decreasing in carbs, non-increasing in
  IOB, and the no-`models`-import AST test.

`tests/safety/test_gates.py`: Gate 2 suite removed; **the whole Gate 1 suite stays** (149 ⇒
closed, 150 + beats baseline ⇒ open, volume alone never opens it, live-not-cached).

`tests/safety/test_safety_invariants.py` / `test_safety_module_hygiene.py`: INV-1's
positive/negative cases removed; **the hygiene rules still hold for every remaining invariant**
— no `assert` in `core/safety.py`, one named function per invariant, zero project imports.

`tests/unit/test_config.py`, `tests/safety/test_config_frozen.py`: `prescriptive_enabled` →
`icr_present`; frozen-ness and the computed-read-only property are still asserted.

**RED evidence:** the new `ValueError` expectations fail against the current gate-raising
implementation (it raises `GateNotPassed`, a `SafetyViolation`), and the renamed config property
does not yet exist.

**Adversarial angle.** The trap here is *silent scope creep in the other direction* — removing
INV-1 and, while in the neighbourhood, weakening INV-3 or INV-4 because they sit in the same
file and the same function. The golden doses, the cap-and-flag assertion, and the BG-80 refusal
are all retained **unchanged** precisely so that any such drift fails the build.
