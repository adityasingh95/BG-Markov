# S-301 — Meal log form ★ (critical path)

**Epic:** 3 (Logging & Durability) · **Safety story:** No (but adherence is the
project's binding constraint) · **Status:** In progress

## Story
The logging flow is the whole project. If a repeat meal takes 90 seconds she
stops in three weeks and it ends with 40 records. So: **a repeat meal is ≤4 taps
+ 2 numbers** (a *tested* requirement, not an aspiration). Optional fields are
collapsed and never block. A draft auto-saves to `localStorage` so a killed or
failed submit never loses input.

## Requirement sources
- **REQ-001** — a repeat meal is loggable in **≤4 taps + 2 numbers**.
- **REQ-002** — pre-BG, meal macros, meal bolus, correction bolus captured per
  meal.
- `05b §3` (logging flow), `05 §1` (`POST /api/meals`).

## Acceptance criteria (backlog)
- [ ] A repeat meal is ≤4 taps + 2 numbers (favourite tap → BG → bolus → timing
      → LOG). Optional fields collapsed, never blocking.
- [ ] `localStorage` draft-save; a killed mid-entry ⇒ draft survives.

## API (`05 §1`)
`POST /api/meals` — reported `datetime` + `pre_bg_time` supplied by the client;
`bolus_offset_min` **required (422 if absent, REQ-003)**; server **stamps
`logged_at`** (never substitutes `now()` for a clinical timestamp), computes
`net_carbs_g` (DB column), writes a `bolus_log` row per bolus component, and
returns `{ meal_id, test_at }` where **`test_at` = reported `datetime` + 120 min**
(never `logged_at + 120`).

## Design
- **`api/deps.py`** — an app engine from `BGAPP_DB_URL` (dev default; tests
  override), a `get_session` FastAPI dependency.
- **`api/schemas.py`** — `MealCreate` pydantic model (offset required).
- **`POST /api/meals`** — builds the meal via the S-202 reported-time path
  (`logged_at` from the injected clock; `datetime` reported), persists, writes
  boluses, returns `test_at`.
- **Meal form (`/`)** — favourites row; tapping a favourite populates the hidden
  macro fields (`carbs/protein/fat/fibre`, `macro_confidence = 95`); BG + bolus
  numbers; signed timing (from S-102); LOG MEAL submits. `app.js` does the
  favourite-populate and the `localStorage` draft-save/restore.
- **Time field** — pre-filled with the current time as an **editable** default
  and **sent by the client** as the reported `datetime` (`05b §3`). This does
  **not** violate ADR-8: ADR-8 forbids the *server* substituting `now()`; a
  visible, editable client default that she can correct is exactly the sanctioned
  behaviour.

### Risk-cue relocation (INV-2)
S-102 put a risk-readout *example* on the index page to test the
colour-not-sole-signal pattern. The real meal-log form must show **no** model
output (INV-2 — nothing patient-visible before Gate 1). So the accessible
primitives gallery (including the risk-cue example) moves to **`/components`**,
and the meal form becomes `/`. The S-102 a11y guarantees (axe, `inputmode`, 48px,
no dish `<select>`, 200 % zoom, signed timing) now run against the **real form**;
the colour-cue test runs against `/components`.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_meals_api.py` (TestClient):
- `POST /api/meals` **without** `bolus_offset_min` ⇒ **422**.
- With a valid payload ⇒ 200; meal persisted; `logged_at` present and **≠**
  `datetime`; a `bolus_log` row written; **`test_at` == `datetime` + 120 min**.

`tests/e2e/test_meal_log_flow.py` (Playwright, live server + temp DB):
- **★ Repeat meal in ≤4 taps:** favourite (1) → type BG → type bolus → timing (2)
  → LOG MEAL (3) ⇒ a confirmation appears. The test performs **≤4 taps** and
  asserts success — the tested form of REQ-001.
- **Draft survives a kill:** fill fields, reload (simulating a kill) ⇒ fields are
  restored from `localStorage`.
- Optional section is collapsed by default.

**RED evidence:** the API route / form / `app.js` absent ⇒ tests fail.

**Adversarial angle:** REQ-001 is a *tested* number. A form that creeps to 5 taps
turns the build red, because adherence is the difference between 150 records and
40.
