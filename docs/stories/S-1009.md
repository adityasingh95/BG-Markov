# S-1009 — Monthly refit cadence

**Epic:** 10 · **Safety story:** No — but it is the first time the model is fitted on her
real data, and the first time the operator's Gate-1 evidence is real · **Status:** ✅ Done
(2026-07-30) · **Requirements:** REQ-060 · **Records:** **DL-047** (the 90-day half-life),
**DL-049** (the `actual_state` gap), **DL-050** (rank-deficient design matrices) ·
**Unblocked by:** S-1013 · **Rollback baseline:** `7a7c3bf`

> `07 §Retraining`: *"Monthly refit, trailing 6 months, older data down-weighted. Promotion
> is manual, on hypo recall."* No schedule exists, and — more to the point — **nothing has
> ever assembled a feature vector from the database.** Every consumer to date has either
> tested a pure function over a hand-built list or fabricated the inputs in memory.

## Story
A refit runs over the trailing six months, weights recent meals more heavily, writes a
**new, unpromoted** model artifact, and the operator's shadow dashboard shows real numbers
instead of an empty state.

---

## ★ The second gap this story found (DL-049)

S-1013 found that `basal_log` had no writer. Scoping this story found the same shape one
table over: **`prediction_log.actual_state` is never backfilled.** The column exists, it is
commented `# backfilled`, and a grep across the tree returns its schema definition and
nothing else.

It matters more than it looks. `actual_state` is *the outcome half of every shadow-mode
comparison.* Without it there is no hypo recall, no Brier score, no calibration curve —
which means `load_shadow_evidence` can never return a report, the dashboard can never show
evidence, and **Gate 1 can never open.** The model would be fitted, correct, and permanently
unreviewable.

The fix is small because the data is already there: the meal's `post_bg` is recorded by
S-303, and `bg_to_state` has existed since S-501. The backfill derives one from the other
for predictions whose meal has since been read. It is *derivation, not entry* — the same
rule as IOB.

**Why it went unnoticed** is worth naming, because it is the third instance: every shadow
test so far passed `pred_states` and `actual_states` **as arrays, directly**, and
`scripts/demo_end_to_end.py` builds both in memory. Nothing had asked the database for an
outcome. *A column nobody has sourced end-to-end is a column nobody has checked is written.*

## Design

### 1. `data/training.py::assemble_training_data(session)` — the missing bridge
Takes the INV-7-enforced training set from `get_training_set` and produces what the model
layer actually consumes:

```
TrainingData(feature_names, x, y_state, confidence_weights, dates, meal_ids)
```

Per meal, the three derived quantities `features.pipeline.feature_vector` requires are
sourced **from the database** for the first time:

| Quantity | Source | Why not the obvious thing |
|---|---|---|
| `iob_at_meal` | `iob_at_start_at(session, meal.datetime)` | Derived from `bolus_log`, never entered — manually-entered IOB is a forbidden pattern |
| `effective_basal` | `basal_doses` → `features.basal.effective_basal`, taking the value **in force at the meal** | Today's dose is not today's effect: Tresiba runs ~42 h with a 3–4 day steady state, so the raw daily figure as a feature is forbidden |
| `minutes_since_last_bolus` | the latest `bolus_log` row strictly before the meal | — |

**`y_state` is `bg_to_state(post_bg)`** — binning the **outcome**, which is the sanctioned
direction. `pre_bg` goes in continuous, as a feature; binning it as an input is forbidden
and has an AST guard.

**★ It goes through `get_training_set`, not its own query.** That function is where INV-7 is
wired: a rescued meal cannot leak into training and every rescued meal must remain a hypo
event. An assembler with its own `select(MealEvent)` would be one line shorter and would
route around the invariant entirely.

### 2. `models/recency.py::recency_weights(dates, *, as_of, half_life_days=90)`
Exponential decay: `0.5 ** (age_days / 90)` (DL-047, operator-approved). A meal from three
months ago counts half as much as one from this week; the oldest in a six-month window about
a quarter.

- **Multiplies into** the existing hypo × macro-confidence weights (S-601). It does not
  replace them, and the order does not matter because multiplication commutes — but the
  *composition* does: all three must be present.
- **★ Never zero.** A rescued low from five months ago is still a low. Recency reduces its
  weight; it must not delete it. The weight is strictly positive by construction (an
  exponential never reaches zero) and there is a test that pins it, because the natural
  "optimisation" — dropping rows below some weight threshold — is exactly the silent
  deletion of old lows this system exists to avoid.
- Ages are computed from an **injected `as_of`**, not `datetime.now()` (ADR-8).

### 3. `models/refit.py::run_refit(...)` — orchestration
Assemble → restrict to the trailing window → weight → temporal CV → fit on the full window →
score → write the artifact.

- **The window is `TRAILING_WINDOW_DAYS = 183`** (`07 §Retraining`, "trailing 6 months").
- **Temporal CV, never a random split** — basal is constant within a day, so a random split
  leaks at the day level. `models.validation.temporal_cv` already exists and is used.
- **The scaler is fit inside the fold**, per S-404.
- **★ The artifact is written with `is_promoted = False`, always.** REQ-060: *"promotion
  never carries over."* A refit that inherited promotion would swap the model she is being
  shown out from under an operator decision that was made about a different model.
- Never overwrites: a new `version` row each time.

### 4. `data/predictions.py::backfill_actual_states(session)` — DL-049
For every `prediction_log` row with `actual_state IS NULL` whose meal now has a `post_bg`,
set `actual_state = bg_to_state(post_bg)`. Idempotent; returns the count filled. The same
shape as `backfill_correction_iob` (S-306b), and for the same reason: a derived column that
a later story turned out to need.

### 5. `python -m cli refit`
One subcommand, alongside `backup` / `export` / `restore-drill`. Prints the version written
and states plainly that it is **not promoted**.

**★ A refit never promotes**, and this is already load-bearing: the S-1001b AST guard
asserts nothing under `cli/` calls `promote_model`. This story is the first code that would
make violating it tempting — the artifact is right there, and one line would "finish the
job". The guard stays.

### 6. `api/app.py::load_shadow_evidence` — wired
Reads the promoted artifact's stored metrics and the backfilled `prediction_log` rows, and
builds a real `ShadowReport`. It keeps failing closed: **no promoted model, or no scored
predictions, still returns the empty state.** An empty dashboard is a true statement about
the evidence; a populated one built from nothing is not.

## Why this is not a `[SAFETY]` story, and where the pressure actually is

It fits a model and writes a row. It shows no dose, opens no gate, and displays nothing to
her. But three of the forbidden patterns converge in this one story, and each would look
like ordinary engineering:

1. **The random train/test split.** It is the default everywhere in the ecosystem and it
   leaks at the day level here.
2. **The raw daily basal dose as a feature.** It is one line and it is wrong for a 42-hour
   insulin.
3. **Dropping low-weight old rows.** It reads as an optimisation and it deletes old lows.

And one invariant sits directly under it: **INV-7**, via `get_training_set`. An assembler
that queries meals itself bypasses the only place the invariant is wired.

---

## TDD strategy (SDET first — written and seen to fail)

`tests/integration/test_refit.py`:
- **★ The artifact is written unpromoted** — `is_promoted is False`, on a database where a
  promoted artifact already exists (so "inherits promotion" fails loudly rather than being
  vacuously true on an empty table).
- **★ A refit never overwrites** — two refits, two rows, the first one unchanged.
- **★ The assembler goes through `get_training_set`** — a rescued meal in the database does
  **not** appear in the assembled rows, and is still counted as a hypo event (INV-7 end to
  end, from the DB rather than from a list).
- **★ `effective_basal` in the assembled vector matches the S-402 EWMA** at that meal's time
  — and is **not** the raw daily dose (assert they differ on a step-change fixture, so the
  forbidden shortcut fails the test rather than passing it by coincidence).
- `iob_at_meal` matches `iob_at_start_at` and is never taken from a stored column.
- **★ Meals outside the trailing 183 days are excluded**; a meal one day inside is kept.
  Boundary, both sides.
- **★ Recency weight is strictly positive at the oldest edge of the window** — an old
  rescued low is down-weighted and **still present**, with its hypo up-weight intact.
- **★ The composition is multiplicative** — a hypo meal with low macro confidence and some
  age carries `confidence × hypo × recency`, asserted against the product, not against any
  one factor.
- A meal from today weighs strictly more than the identical meal from 90 days ago, and the
  ratio is 2 (the half-life, pinned).
- `y_state` is derived by `bg_to_state` from `post_bg`; `pre_bg` appears **continuous** in
  the feature vector.
- **★ `backfill_actual_states` fills only where the meal has a `post_bg`**, is idempotent,
  and leaves a prediction whose outcome is not yet known as `NULL` — "not yet known" and
  "state 3" must never be the same value.
- **★ `load_shadow_evidence` still returns the empty state with no promoted model**, and
  returns a real report once one exists with scored predictions.
- `cli refit` writes a row and its output says the artifact is not promoted.

`tests/forbidden/` — the existing guards already cover the binner, the raw basal dose, and
`cli/` → `promote_model`. This story is the first code with a real motive to trip all three;
the tests assert they still hold with the refit present.

**RED evidence:** `data.training`, `models.recency`, `models.refit` do not exist;
`backfill_actual_states` does not exist; `python -m cli refit` is an unknown subcommand.

**Adversarial angle.** Four, in descending order of how reasonable each looks:
(a) the assembler running its own `select(MealEvent)` instead of `get_training_set` — one
line shorter, routes around INV-7;
(b) dropping rows whose recency weight falls below a threshold — reads as an optimisation,
silently deletes old lows;
(c) a random split for the CV — the ecosystem default, leaks at the day level;
(d) the refit carrying `is_promoted` forward from the previous artifact — feels like
continuity, and swaps the served model out from under an operator decision.

### ★ The adversarial pass found a real hole — a plant SURVIVED

Four plants on a clean committed tree (`181d060`). Three died. **One did not**, and it is
the one CLAUDE.md warns about by name.

| Plant | Result |
|---|---|
| a private `select(MealEvent)` bypassing `get_training_set` | caught — but by **only one** test, see below |
| **dropping rows whose recency weight falls below a threshold** | **★ SURVIVED — all 22 tests green** |
| a shuffled `KFold` instead of forward chaining | caught (`TemporalLeakageError`, re-asserted per fold) |
| the refit inheriting `is_promoted` | caught (the artifact test **and** the S-1001b AST guard) |

**Why (b) survived.** `test_recency_weight_is_strictly_positive_at_the_oldest_edge` asserts
on `recency_weights` — the **pure function**. Production does not call the pure function; it
calls `composite_weights`. Planting `np.where(combined < 0.35, 0.0, combined)` there — one
line, reads as housekeeping — left the suite entirely green.

**Why it matters.** A row weighted `0.0` is a row that was not in the fit. The rows that
reach zero first are the oldest, and after the hypo up-weight those are disproportionately
the **rescued lows**. This is CLAUDE.md's sentence about INV-7, arriving through a different
door: *"the obvious refactor silently deletes exactly the lows the system exists to
predict."*

Two tests now assert on the **composition**, over a worst-case row (oldest in the window,
lowest confidence that still passes S-203 validity). Re-planting (b) fails them.

> **The recurring shape, now three-for-three:** S-1005 caught *the plant did nothing*;
> S-1013 caught *the plant did too much* and *the plant broke the wrong thing*; this caught
> **the guard was one layer away from the thing that runs.** Testing a pure function proves
> the function. It proves nothing about the composition production actually calls.

### ★ A second finding: a ★-labelled test that does not do its job

`test_a_rescued_meal_is_absent_from_training_and_still_a_hypo_event` was labelled *"THE ONE
THAT CATCHES THE SHORTCUT."* It is not. A plant replicating `get_training_set`'s validity
logic **minus the INV-7 call** leaves it green — a hypo-rescued meal fails S-203 validity
anyway, so it is excluded whichever route the assembler takes.

The test that **does** catch the bypass is the ledger-reconciliation one: validity filtering
can reach *"the rescue is absent from training"* on its own, but nothing except INV-7 can
reach the reconciliation. Both relabelled honestly, and a non-emptiness assertion added —
under the first plant the training set came back **empty**, and *"the rescue is not in it"*
was true of nothing at all.

### Four production defects the implementation surfaced (not fixture problems)

1. **`statsmodels` refuses a design matrix whose column span contains a constant.** A real
   six-month window trips this two ways: a constant column (no intense exercise all window)
   and a constant *combination* (`net_carbs_g` is `carbs_g − fiber_g`, so wherever fibre does
   not move they differ by a fixed amount). A plain is-this-column-constant check catches
   only the first. The filter is **rank-based**: keep a column iff it raises the rank of
   `[1 | kept]`. Unhandled, the monthly refit would die with a statsmodels message saying
   nothing about her data, **on the day it first met a real six months**. (DL-050.)
2. **The same check must run per CV fold** — a column can carry rank across the whole window
   and be redundant inside an early expanding-window fold.
3. **Hypo recall is undefined when a window contains no lows** — recorded as `null`, never
   `0.0`. A recall of zero reads as *"it missed every low"*; a window with no lows means the
   model has never seen the event it exists to predict, and Gate 1's beats-baseline condition
   has nothing to compare. Opposite meanings, one number.
4. **`feature_list` records what was *actually fitted*,** with the rest named in
   `dropped_constant_features`. The manifest answers *"what did this model see?"* — "all 23"
   would be false whenever a column carried no rank.

### Deviations from the design above
- `feature_list` is the fitted subset, not `FEATURE_NAMES` (item 4). The SDET test was
  updated to the truthful contract, asserting **both** that it is a subset and that fitted ∪
  dropped is exhaustive — a subset alone is satisfiable by dropping everything silently.
- `data/scoring.py` was added; the design put the scoring read inside `load_shadow_evidence`.
  It is a DB accessor and belongs with the other DB accessors.
- `is_promoted` is **not passed** to `ModelArtifact` at all. Passing `False` reads as
  harmless and would trip the S-1001b guard, which forbids any module outside
  `data.promotion` writing the flag — including writing it False. The refit now *cannot*
  mint a promoted artifact rather than choosing not to.

### Still open — raised, not silently resolved
- **`unconstrained_beta_insulin` is not recorded by a refit.** The shadow report's
  β_insulin < 0 confounding alarm therefore reads 0.0 (no alarm) rather than a measured
  value. `07 §6`/S-503 computes it; wiring it into the artifact manifest is a small follow-up
  and is **not** done here. Until it is, **the confounding alarm on the operator dashboard is
  not armed** — flagged prominently because a dark alarm looks identical to a quiet one.
- **`predicted_bg` / `reference_bg` on the shadow report are state midpoints.**
  `prediction_log` stores a distribution over states, not a predicted mg/dL, so MAE and the
  Clarke grid are computed on a coarse stand-in. Recorded rather than presented as accuracy
  the log cannot support.
- **The backfill is on-demand only.** Whether recording a `post_bg` should also fill
  `actual_state` immediately is the operator's call (DL-049); adding a write to a capture
  surface she uses daily is not a change to make unasked.
