# S-1008 — Live prediction wiring (per-meal orchestration)

**Epic:** 10 · **Safety story:** No `[SAFETY]` label, but it **carries INV-9 and INV-2 through
the wiring** — see the ordering argument below · **Status:** In progress ·
**Requirements:** REQ-059 · **Depends on:** S-1004 (fixtures) · **Feeds:** S-1002, S-1005 ·
**Rollback baseline:** `7a7c3bf`

> **Pure wiring. No new model logic.** Every component already exists and is tested. This story
> is about the *order* they are called in, because that ordering is where INV-9 and INV-2 either
> hold or quietly stop holding. A component can be individually correct and the chain still
> unsafe.

## Story
On a logged meal, run the real path over shipped modules:
`features → promoted model → guardrails → persist (INV-9) → serve`.

## The one design decision worth stating plainly

**Prediction is not gated. Display is.**

Shadow mode means *"the model predicts; predictions are logged and compared to actuals; nothing
is shown to the patient"* (`00-glossary`). So this orchestration **always predicts and always
logs**, even with Gate 1 shut — that is the entire mechanism by which 90 days of evidence
accumulates. `require_gate1` belongs on the **readout** (S-1002), not here.

Getting this backwards in either direction is a real failure:
- Gating *prediction* on Gate 1 ⇒ the shadow clock never accrues evidence, and Gate 1 can never
  legitimately open. The system would deadlock itself and look like it was being careful.
- Gating *nothing* ⇒ INV-2 is breached and she sees an unproven model.

## Design — `prescribe/serving.py`

```
serve_meal_prediction(session, meal, *, features, ...) -> MealPrediction
    1. baseline_state   = predict_baseline_state(...)      # always available, always causal
    2. promoted         = get_promoted_artifact(session)   # NEW, data/repositories.py
    3. if promoted is None:  return MealPrediction(baseline_state=..., served=None)
    4. proba            = model.predict_proba(features)
    5. guarded          = guard_prediction(..., baseline_state=baseline_state)
    6. served           = serve_prediction(session, guarded, ...)   # ★ INV-9 write-before-return
    7. return MealPrediction(baseline_state=..., served=served, model_version=...)
```

- **`MealPrediction`** — frozen dataclass: `baseline_state: int`, `served: ServedPrediction | None`,
  `model_version: str | None`. `served is None` means *no model was promoted*, which the readout
  renders as the baseline.
- **`get_promoted_artifact(session)`** — new in `data/repositories.py`. Returns the single
  promoted `ModelArtifact` or `None`. **Fails closed:** no promoted row ⇒ `None` ⇒ baseline only.
  This is the *first code in the project to read `is_promoted`* (it has existed unread since
  S-201). Note it reads it to answer **"which model serves?"** — S-1006 separately makes Gate 1
  *require* promotion, answering **"may she see it?"** Two different questions, same flag.
- **No model logic is added.** `predict_proba`, `guard_prediction`, `serve_prediction`,
  `predict_baseline_state` are all called unchanged.

## Why the ordering is the safety property

1. **INV-9 — persisted before returned.** `serve_prediction` is the *only* way this module
   returns a model result, and it persists first (S-802). There is no branch that constructs a
   servable value some other way, so a prediction cannot escape unlogged. If persistence raises,
   the exception propagates and **nothing is served** — it never degrades into an unlogged
   prediction.
2. **No promoted model ⇒ baseline, never a raw model output.** The `promoted is None` branch
   returns *before* any model call. There is no code path where an unpromoted model's output
   reaches a caller.
3. **The baseline is computed first and unconditionally.** It is causal, always available, and is
   the kill-switch fallback (S-803). Computing it up front means every return carries a usable
   answer even when the model path refuses.
4. **Guardrail refusals propagate as values, not exceptions.** `guard_prediction` returns a
   refusing `GuardedPrediction`; the refusal is *persisted like any other prediction* and handed
   on, so a refusal is auditable and renderable — never a blank.

## TDD strategy (SDET first — written and seen to fail)
`tests/integration/test_serving.py`:
- **★ INV-9 — mock the persistence layer to fail ⇒ NOTHING is served.** The strongest test here;
  it is the S-802 discipline re-asserted *through the wiring*.
- **★ INV-9 ordering — the row exists in `prediction_log` before the return value is observable**
  (assert the returned `prediction_id` resolves to a real persisted row).
- **★ No promoted model ⇒ `served is None` and a usable `baseline_state`; `predict_proba` is
  never called** (spy on the model — asserting the *absence of a call*, not just the shape of the
  output).
- **★ Promoted model ⇒ it is the one used** (version on the served row matches the promoted
  artifact) — proves `get_promoted_artifact` is wired, not decorative.
- **Guardrail refusal propagates** as a persisted, refusing `GuardedPrediction` (not an
  exception, not a blank).
- **Prediction is NOT gated:** with Gate 1 shut, serving still predicts and still logs — the
  shadow-mode mechanism. Paired with an assertion that this module **never calls
  `require_gate1`** (AST), so the gate cannot drift from the readout into the predictor.
- **INV-6 still bites through the chain:** an absurd `predicted_bg` raises rather than being
  downgraded to a refusal.
- `get_promoted_artifact` — none ⇒ `None`; one ⇒ that one; **unpromoted rows are ignored**.

**RED evidence:** `prescribe/serving.py` and `get_promoted_artifact` do not exist.

**Adversarial angle.** Three cheap mistakes: (a) calling `require_gate1` here "to be safe", which
silently stops shadow mode from ever accruing evidence; (b) building a return value on a path
that skipped `serve_prediction`, which breaks INV-9 while every unit test still passes; and
(c) falling back to *the most recent* artifact rather than the *promoted* one when none is
promoted — which would quietly serve an unpromoted model. Each has a test.
