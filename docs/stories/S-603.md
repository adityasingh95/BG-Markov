# S-603 — Bayesian ordinal (n ≥ 200)

**Epic:** 6 (The Model) — **closes EPIC 6** · **Safety story:** Yes (INV-8 encoded in
the prior) · **Status:** In progress · **Requirements:** REQ-031, **INV-8**

> **At single-patient sample sizes, a point estimate is a lie dressed as precision.**
> The honest object is a *posterior* — credible intervals that are wide when the data
> is thin and narrow only when it earns it. And the prior is where INV-8 lives most
> naturally: a sign-constrained prior on the insulin coefficient gives zero density to
> "insulin raises glucose" **before a single data point is seen**, so no amount of
> confounded data can move the posterior across zero. This is the model spec's chosen
> form at n ≥ 200 (07 §8).

## Story
Fit a Bayesian ordinal (proportional-odds) model with `PyMC` `OrderedLogistic`,
weakly-informative priors, and a **sign-constrained (half-normal) prior on the insulin
coefficient** so INV-8 is encoded natively. Report **credible intervals**, not point
estimates; the intervals widen as `n` shrinks. Production use of this model is gated at
`n ≥ 200` (07 §8) — `MIN_BAYESIAN_N`.

## Design
`models/bayesian_ordinal.py` (pure — `models/` holds the estimators):

- **Model.** `pm.OrderedLogistic("y", eta, cutpoints, observed=y0)` over 0-indexed
  states. `eta = X_other·β_other − insulin·β_insulin` — the insulin term enters with a
  **negative sign**, because higher insulin lowers glucose (lowers the state).
  - `β_insulin ~ HalfNormal(σ)` — **support ≥ 0 by construction.** This *is* the INV-8
    sign constraint: every posterior draw of `β_insulin` is ≥ 0, so the model can never
    place mass on "insulin raises glucose". (Defining `β_insulin` as the non-negative
    sensitivity magnitude matches S-503 and `inv8_beta_insulin_non_negative`.)
  - `β_other ~ Normal(0, 1)` — weakly informative on the remaining, standardised
    features.
  - `cutpoints ~ Normal(0, 5)` under an **ordered** transform (monotone thresholds).
- **`fit_bayesian_ordinal(x, y, *, insulin_col, draws, tune, chains, seed) ->
  BayesianOrdinalFit`** — samples (NUTS), returns the `β_insulin` draws (all ≥ 0), a
  `credible_interval(...)` accessor (arviz HDI), and `n`. Wires
  `inv8_beta_insulin_non_negative` on the **minimum** draw — a hard stop if any draw is
  negative (it cannot be, by construction, but the invariant is asserted, never
  assumed).
- **`MIN_BAYESIAN_N = 200`** and **`bayesian_gate_open(n) -> bool`** — the 07 §8
  production gate (when to switch from the frequentist ordinal to this one). The
  *estimator* fits at any identifiable `n` (that is how the widening property is
  demonstrated); the **gate** governs production use and is checked by the caller.
- **`CredibleInterval(lower, upper)`** with a `width` property.

**Toolchain (DL-027).** `PyMC` is added as a pinned dependency (user-approved, 2026-07-17).
It pulls a heavy stack (`pytensor`, `numba`, `arviz`) and constrains `numpy` to `2.4.x`,
so `numpy` is now explicitly pinned `==2.4.6`. Sampling compiles a `pytensor` C graph
(g++ present in CI); the first compile dominates wall-time and is disk-cached.

## Written safety argument (why INV-8 holds) [SAFETY]
1. **The constraint is the prior's support, not a post-hoc clamp.** `β_insulin ~
   HalfNormal` has density 0 on `(−∞, 0)`. The posterior is `prior × likelihood`, so it
   too has zero density below 0 — **every draw is ≥ 0 by construction**, for any data,
   including maximally confounded data where the likelihood alone would pull negative.
2. **The invariant is still asserted.** `inv8_beta_insulin_non_negative(min(draws))`
   runs on the sampled minimum — the guard bites if a future refactor swaps the prior
   for an unconstrained `Normal`. A green sample is not trusted on faith.
3. **Direction is explicit.** Insulin enters `eta` with a negative sign, so a
   non-negative `β_insulin` means insulin can only **lower** the predicted state — never
   raise it. There is no parameterisation in which a valid draw makes insulin raise
   glucose.
4. **No dose path touches this (ADR-10).** The ML never sets a dose; this posterior
   informs ICR/ISF review and risk read-out only.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_bayesian_ordinal.py` (synthetic data: glucose rises with carbs, falls
with insulin; insulin correlated with carbs so the *likelihood* is confounded):
- **★ Posterior support is one-sided.** Every `β_insulin` draw is `≥ 0` — the sign
  constraint holds on confounded data where a naive fit would go negative.
- **Credible intervals, not point estimates.** The 94% HDI for `β_insulin` has
  **positive width** (`upper > lower`) — the output is an interval, not a single number.
- **Intervals widen as n shrinks.** The HDI width at small `n` is **greater** than at
  large `n` — thin data yields honest uncertainty, not false precision.
- **INV-8 wired.** `inv8_beta_insulin_non_negative` is called on the draws and does not
  raise; the guard still bites on a hand-constructed negative.
- **Gate.** `bayesian_gate_open(199)` is `False`; `bayesian_gate_open(200)` is `True`.

**RED evidence:** `models/bayesian_ordinal.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the trap is to fit an *unconstrained* Bayesian model "to let the
data speak" — and on confounded single-patient data the data says insulin raises
glucose. The one-sided-support test is the tripwire: it asserts the prior's constraint
survives into the posterior, so no confounded likelihood can produce a draw that, fed
into a dose, would drive a low she cannot feel.
