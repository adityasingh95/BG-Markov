# S-602 — Brant test + partial proportional odds

**Epic:** 6 (The Model) · **Safety story:** No (but a mis-specification guard) ·
**Status:** In progress · **Requirements:** REQ-031 (07 §8 escalation path, step 1–2)

> **The ordinal model assumes proportional odds — one slope vector shared across every
> threshold. That assumption is testable, and here it is plausibly wrong:** exercise
> may act non-monotonically across the BG thresholds (intense exercise can *raise* BG),
> so a single slope for `ex_intense` cannot be right at both the hypo boundary and the
> hyper boundary. If the assumption fails and we say nothing, the model quietly mis-fits
> exactly where the states matter most. This story is the after-every-fit check that
> makes that failure **loud**: a Brant test, and a typed escalation when it rejects.

## Story
After fitting the ordinal model (S-601), run a **Brant test** for proportional odds.
On rejection, **escalate** — raise a typed `ProportionalOddsViolation` carrying which
predictors violate — rather than silently accepting a mis-specified model. Partial
proportional odds (freeing the offending slopes) is the named next step (07 §8 step 2).

## Requirement source
- **07 §8 — Escalation path.** (1) *Brant test for proportional odds after every fit.*
  (2) *If it fails — plausible, since exercise may act non-monotonically across
  thresholds — partial proportional odds.* (3) At n ≥ 200, Bayesian ordinal (S-603).
- **CLAUDE.md — Escalate, do not decide.** A mis-specified model is not something Dev
  papers over; the violation is surfaced with the evidence (which predictor, what
  p-value) so the modelling choice is made deliberately, not by default.

## Design
`models/brant.py` (pure — depends only on `numpy` + `scipy.stats`, no project imports
beyond none; the per-threshold logits are fit locally):

- **Per-threshold binaries.** For a response with observed ordered states `s₁<…<s_J`
  and thresholds `t₁…t_{J-1}`, fit `J-1` binary logits of `z_k = 1[y > t_k]` on the
  design `[1, X]`. `statsmodels`' discrete `Logit` is unusable under the pinned
  toolchain (`statsmodels.api` → `scipy 1.18` removed `_lazywhere`, an ImportError; see
  DL-026), so the binary fit is a small, deterministic Newton–Raphson with a
  ridge-stabilised Hessian — no dependency on the broken import path.
- **Brant covariance (Brant 1990).** Stack the slope estimates `β̂_k` (intercepts
  dropped). Block `(k,l)` of the covariance is
  `(XᵀW_kX)⁻¹ (XᵀW_{kl}X) (XᵀW_lX)⁻¹`, with `W_k = diag(π_k(1−π_k))` and, for `k<l`,
  `W_{kl} = diag(π_l(1−π_k))` (since `1[y>l] ⇒ 1[y>k]`, so
  `Cov(z_k,z_l)=π_l−π_kπ_l`).
- **Statistics.** Omnibus contrast `D` encodes `β_k = β_{J-1}` for all `k`;
  `X² = (Dβ̂)ᵀ(D V̂ Dᵀ)⁻¹(Dβ̂)`, `df = p·(J-2)`. A per-predictor contrast gives one
  `χ²`/`p`-value per feature (`df = J-2`) — this is what names the **violators**.
- **`brant_test(x, y, *, alpha=0.05) -> BrantResult`** — pure; `holds = omnibus_p ≥
  alpha`; `per_predictor` and `violators` (indices with per-predictor `p < alpha`).
- **`check_proportional_odds(x, y, *, alpha=0.05) -> BrantResult`** — the after-every-fit
  gate: returns the result when PO holds; **raises `ProportionalOddsViolation(result)`**
  when it does not. That raise *is* the escalation.

**Out of scope — the partial-PO *fitter* (deferred, DL-026).** 07 §8 names partial
proportional odds as the response to a rejection, but *fitting* one (freeing only the
violating slopes) is a modelling decision that (a) is meaningless until there is real
data to reject on — this whole epic is gated behind live collection — and (b) must be
chosen deliberately, not defaulted by Dev. S-602 delivers the **detection + the typed
escalation that identifies exactly which slopes a partial-PO model would free**
(`violators`). The fitter lands when a real Brant rejection on real data demands it.
Building an untested partial-PO fitter now would be speculation, and the escalate rule
says surface the decision, not pre-empt it.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_brant.py`:
- **PO-satisfying data passes.** Data from a single latent (`0.9·pre_bg + … + logistic
  noise`) binned by the state boundaries ⇒ `brant_test(...).holds is True`, omnibus
  `p` comfortably above `alpha`; `check_proportional_odds(...)` returns **without
  raising**.
- **★ Threshold-varying data fails and escalation fires.** Data generated with a
  slope on `x₁` that changes across thresholds (shared-uniform latent coupling,
  `γ = [3, 1, 1, −3]`) ⇒ `holds is False`, omnibus `p ≪ alpha`, and
  `check_proportional_odds(...)` **raises `ProportionalOddsViolation`**.
- **Violators are named.** On the threshold-varying data (only `x₁` non-proportional,
  `x₂` inert), `x₁`'s index is in `violators` and `x₂`'s is not — so a partial-PO fit
  would free the right slope.
- **Shapes/df.** `omnibus_df == p·(J-2)`; one `PredictorBrant` per feature with
  `df == J-2`.

**RED evidence:** `models/brant.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the trap is to fit the ordinal model, get plausible-looking
probabilities, and never test the assumption underneath them — a mis-fit that is
invisible on the surface. The threshold-varying test is the tripwire: it *looks* like
ordinal data (five ordered states, monotone-ish) but the shared slope is a lie, and the
Brant gate must reject it and refuse to proceed silently.
