# S-901 [SAFETY] — Bolus calculator

**Epic:** 9 (Prescriptive — Gate 2) — **the last story** · **Safety story:** Yes, the
sharpest end · **Status:** In progress · **Requirements:** REQ-041, REQ-042, REQ-043,
**INV-1**, **INV-3**, **INV-4**

> **This is the only place in the system that recommends putting insulin into a person who
> cannot feel a low.** So it uses arithmetic she has done by hand for 30 years — not a
> model — it refuses when she is already low, it treats an impossible carb entry as a typo
> instead of a lethal dose, and it shows its full working and calls itself a *suggestion for
> review*, never an instruction. It exists at all only because the code gate (S-703) and the
> **human gate** (endocrinologist ICR/ISF sign-off, OQ-1/OQ-2, DL-032) are both cleared.

## Story
Implement the prescriptive bolus calculator behind `recommend_bolus`'s live Gate-2 check:
the standard clinical formula (no ML), refusing below BG 80 (INV-4), capping at 15 U **and
flagging** an implausible input rather than silently clipping a typo (INV-3), never negative
(INV-3), gated on a confirmed ICR (INV-1). It shows the full arithmetic and frames the number
as a suggestion for review.

## Requirement source
- **07 §11** — `carb_dose = carbs_g/icr; correction = (current_bg − target_bg)/isf; return
  max(0.0, carb_dose + correction − iob)`. *"The standard clinical formula. Causal by
  construction. No model output enters this path."* Show the full arithmetic; frame as a
  suggestion for review.
- **INV-1** — disabled until Gate 2 (a confirmed ICR); hard block, no bypass.
- **INV-4** — refuse below BG 80 → "treat the low first."
- **INV-3** — cap at `MAX_BOLUS_U` (15 U), **a cap event is flagged as implausible input,
  never silently clipped**; never negative.
- **OQ-1/OQ-2/OQ-6 (DL-032)** — ICR = 9 g/U, ISF = 30 mg/dL/U, target = 135 mg/dL, all
  clinician-confirmed; stored in the versioned `patient_profile`, read as parameters (never
  hardcoded), updatable by a new profile version.

## Design
`prescribe/bolus.py` — replace the EPIC-9 placeholder with the calculator:

- **`BolusRecommendation`** — `total_units`, `carb_dose`, `correction_dose`,
  `iob_subtracted`, `capped: bool`, `implausible_input: bool`, `arithmetic: str` (the full
  working, shown), `framing: str` ("a suggestion for review, not an instruction").
- **`recommend_bolus(*, icr, isf, carbs_g, current_bg, target_bg, iob) ->
  BolusRecommendation`**:
  1. **INV-1 first:** `require_gate2(gate2_status(icr=icr))` — `icr = None` ⇒ `GateNotPassed`;
     no `force`/`override`/env/flag bypass, evaluated live every call (ADR-7).
  2. **INV-4:** `inv4_bolus_allowed_at_bg(current_bg)` — BG < 80 raises; the caller renders
     "treat the low first."
  3. **Clinical formula (no ML):** `carb_dose = carbs_g/icr`, `correction = (current_bg −
     target_bg)/isf`, `raw = carb_dose + correction − iob`, `dose = max(0.0, raw)`.
  4. **INV-3 cap + flag:** if `dose > MAX_BOLUS_U`, set `implausible_input = True` and
     `capped = True`, and cap to `MAX_BOLUS_U` — a typo (`carbs = 900`) is **flagged**, not
     silently dosed. `inv3_bolus_within_bounds(dose)` is the final belt-and-braces
     (`0 ≤ dose ≤ 15`, raises otherwise).
- **No ML in this path.** The function imports no model; the only inputs are the clinical
  constants (from the profile) and the current meal/BG/IOB. The forbidden-pattern guards
  already ensure no model class appears; this module composes none.

**Contract change (S-703 → S-901).** `recommend_bolus` previously took only `icr` and raised
`NotImplementedError` when the gate opened (the EPIC-9 placeholder). It now takes the full
clinical inputs and computes. The S-703 gate tests that asserted the placeholder are updated
by SDET to the real contract — `icr = None` still ⇒ `GateNotPassed`, and the no-bypass
property is re-asserted against the real calculator.

## Written safety argument (why a typo cannot become a lethal dose, and no dose escapes the gate) [SAFETY]
1. **Gate first, no bypass.** The first statement is `require_gate2` → `inv1_…`
   (`core/safety.py`). With `icr = None` it raises and the function cannot reach the formula.
   No parameter, env var, or flag skips it.
2. **The low is treated before the meal.** `inv4_bolus_allowed_at_bg` raises at BG < 80 before
   any arithmetic — the calculator will not add insulin to someone already low.
3. **A typo is flagged, not dosed.** An implausible carb entry drives the raw dose over 15 U;
   INV-3 caps to 15 **and sets `implausible_input`**, so the operator sees a flag, not a
   silently-clipped "confident" 15 U. `inv3_bolus_within_bounds` then re-asserts the bound.
4. **Never negative.** A below-target correction that would drive the dose negative is floored
   at 0.0 (`max(0.0, …)`), re-asserted by INV-3.
5. **No model can move the dose.** The formula is causal arithmetic on clinical constants;
   there is no model call in the path, so a mis-fit or confounded model (which the whole rest
   of the system guards against) can never reach the needle.
6. **It is advice, shown in full.** The arithmetic is returned in the open and framed as a
   suggestion for review — she checks the maths, as she has for 30 years.

## TDD strategy (SDET, written first — seen to fail)
`tests/safety/test_bolus.py` (ICR 9, ISF 30, target 135):
- **★ INV-4:** BG 79 ⇒ `SafetyViolation`; BG 80 ⇒ computes.
- **★ INV-3 cap + flag:** `carbs_g = 900` (typo for 90) ⇒ `total_units == 15.0` **and**
  `implausible_input is True` **and** `capped is True`. Assert **both**.
- **INV-3 negative:** a below-target correction with no carbs ⇒ `total_units == 0.0`.
- **★ INV-1 no bypass:** `icr = None` ⇒ `GateNotPassed`; no `force`/`override`/`skip_gate`
  parameter; bypass-looking env vars do not produce a dose.
- **★ Golden — 5 hand-computed doses to 2 dp:** `(90,180,0)→11.50`, `(45,135,0)→5.00`,
  `(60,200,2)→6.83`, `(30,120,0)→2.83`, `(0,90,0)→0.00`.
- **Property — non-decreasing in carbs:** more carbs ⇒ dose ≥.
- **Property — non-increasing in IOB:** more IOB ⇒ dose ≤.
- **No ML:** `prescribe/bolus.py` imports nothing from `models/`.
- **Arithmetic shown / framed as review:** the recommendation carries the full working and a
  review framing, never an imperative.
- **`tests/safety/test_gates.py` updated** to the new `recommend_bolus` contract (placeholder
  `NotImplementedError` expectations replaced; `icr=None ⇒ GateNotPassed` + no-bypass kept).

**RED evidence:** `BolusRecommendation` does not exist and `recommend_bolus`'s new signature
is absent ⇒ import/type errors before impl.

**Adversarial angle:** the two traps are (a) letting a model "improve" the dose — blocked
because no model is imported and the formula is fixed arithmetic; and (b) silently clipping a
`carbs = 900` typo to a confident 15 U — blocked because the cap is a *flag*, so the operator
is told the input is implausible instead of being handed a lethal-looking recommendation.
