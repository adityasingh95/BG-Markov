# S-401 [SAFETY] — IOB engine (Fiasp)

**Epic:** 4 (Derived Features) — first story past the ship line · **Safety story:**
Yes · **Status:** In progress · **Requirements:** REQ-020

> Insulin-on-board is the single most confounding quantity in dosing. It **must be
> derived** from the injection log, never entered by hand — a mistyped or stale IOB
> silently changes every downstream correction, and this patient cannot feel the
> low that results. The forbidden-pattern guard (`detect_manual_iob`) exists for
> exactly this; S-401 gives it a real, derived site to stand next to.

## Story
A pure IOB engine: the fraction of a bolus still active `t` minutes after
injection (the Fiasp exponential activity curve, `tp=55`, `td=240`), and
`iob_at(at, boluses)` summing the live fraction of every prior injection from
`bolus_log`. No manual-entry path exists anywhere.

## Requirement source
- **REQ-020** — IOB derived from `bolus_log` via an exponential model (Fiasp:
  peak `tp=55` min, duration `td=240` min). **Always derived; no manual entry.**
- **CLAUDE.md forbidden pattern** — "Manually-entered IOB → must be derived →
  `iob_at(timestamp)` from `bolus_log`."
- **06 §arch** — `features/` holds IOB · basal · exercise. This story creates the
  `features/` package.

## The curve
The standard exponential insulin-activity model (LoopKit / OpenAPS), parameterised
by peak `tp` and duration `td`:

```
tau = tp·(1 − tp/td) / (1 − 2·tp/td)
a   = 2·tau/td
S   = 1 / (1 − a + (1 + a)·e^(−td/tau))
IOB(t) = 1 − S·(1 − a)·( (t²/(tau·td·(1−a)) − t/tau − 1)·e^(−t/tau) + 1 )   for 0 < t < td
IOB(t) = 1   for t ≤ 0   (clock skew / pre-injection)
IOB(t) = 0   for t ≥ td
```

With `tp=55, td=240`: `tau≈78.269`, `a≈0.6522`, `S≈2.3544`.

## Design
- **`features/iob.py`**:
  - `iob_fraction(t_min: float) -> float` — the curve above; clamps to 1 for
    `t ≤ 0`, 0 for `t ≥ td`.
  - `iob_at(at: datetime, boluses: Iterable[(datetime, units)]) -> float` —
    `Σ units · iob_fraction((at − bolus_time) in minutes)`. Linear in units, so it
    is **additive**: two 5 U boluses at one instant equal one 10 U bolus.
  - `TP_MIN = 55.0`, `TD_MIN = 240.0` constants with the REQ reference.
- **No input path.** IOB is computed from injection times + units only. There is no
  parameter, column, or request field that sets IOB directly — proven by the AST
  guard scanning every package.
- Pure functions; no clock read (the caller passes `at`), no DB coupling (the
  caller supplies the boluses, typically from `bolus_log`).

## Safety argument (why this is safe) [SAFETY]
1. **Derived, not entered.** IOB has exactly one source: the activity curve applied
   to logged injections. `detect_manual_iob` (S-105) scans all packages for `iob`
   assigned from a request/form/payload; S-401 adds the real derived site and the
   guard stays clean — the negative proof that no input path exists.
2. **Bounded.** `iob_fraction ∈ [0, 1]` for all `t` (property test over a dense
   grid), so IOB can never exceed the units actually delivered.
3. **Monotone decay.** Strictly decreasing on `(0, td)` — insulin only clears, never
   re-accumulates. A non-monotone curve would let IOB *rise* with time and
   under-count active insulin, biasing a correction upward toward a low. This is the
   core correctness property.
4. **Locked shape.** Six hard-coded `(t, fraction)` golden values to 4 dp pin the
   curve so a refactor cannot silently reshape it.
5. **`iob_at_start` deferral (DL-020) is now dischargeable.** S-306 left
   `correction_event.iob_at_start` NULL pending this engine; a later story
   backfills it via `iob_at()`.

## Out of scope

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_iob.py`:
- **Property — monotone decreasing on (0, td):** for a dense grid of `t`,
  `iob_fraction(t+Δ) < iob_fraction(t)`. The core property.
- **Property — range [0, 1]:** `0 ≤ iob_fraction(t) ≤ 1` for all `t` in
  `[−10, 300]`; `f(0)=1`, `f(240)=0`, and `f(−5)=1` (clock skew clamps to full).
- **Golden — 6 pairs to 4 dp:** `(0,1.0000)`, `(30,0.8763)`, `(55,0.6839)`,
  `(120,0.2394)`, `(180,0.0449)`, `(240,0.0000)`. Locks the curve.
- **Additivity:** `iob_at` of two 5 U boluses at one instant == one 10 U bolus,
  and == `10 · iob_fraction(elapsed)`.
- **AST:** no module assigns IOB from a user-input source (`detect_manual_iob`
  clean across the tree — already in the forbidden suite; S-401 keeps it green with
  a real derived site present).

**RED evidence:** `features/iob.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the tempting shortcut is a linear decay (`1 − t/td`) — simpler,
and wrong: it mis-times the peak and under-states early IOB, so a correction stacked
20 min after a meal bolus would double-dose toward a low. The golden pairs and the
monotone/peak shape pin the real curve.
