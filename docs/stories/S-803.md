# S-803 [SAFETY] — Kill switch

**Epic:** 8 (Guardrails & Output) · **Safety story:** Yes · **Status:** Done ·
**Requirements:** REQ-047

> **When the model drifts below the baseline it was supposed to beat, it must stop
> speaking — and stay stopped.** The dangerous failure is not the trip; it is the *quiet
> un-trip*: a model that degraded, got switched off, then happened to produce one good
> prediction and silently turned itself back on. A human, not a lucky data point, decides
> when it is safe to trust again.

## Story
Provide a kill switch that **trips** when rolling prospective performance falls below the
clinical baseline (drift), suppresses ML output in favour of the baseline, and — the
load-bearing property — **never re-arms itself**. Once tripped, the flag is cleared by a
**manual operator action only**; no subsequent good prediction, and no automatic
evaluation, can turn it back on.

## Requirement source
- **REQ-047** — kill switch on drift; **re-arming is manual only.**
- **08 scenarios** — rolling prospective performance below the clinical baseline ⇒ ML
  output suppressed, baseline shown, operator alerted; *"Given the kill switch has
  tripped, when a subsequent prediction happens to be good, ML output remains suppressed,
  and only a manual operator action re-arms it."*
- **07 §…** — the baseline is the fallback when the kill switch trips.

## Design
`prescribe/kill_switch.py` (the gated-output package; persists on `model_artifact`):

- **`should_trip(*, rolling_recall, baseline_recall) -> bool`** — drift is
  `rolling_recall < baseline_recall`: the model must keep **beating** the baseline on hypo
  recall to keep speaking. (Consumes the S-702 metric.)
- **`evaluate_kill_switch(session, model_version, *, rolling_recall, baseline_recall) ->
  bool`** — evaluates drift and, if drifting, **trips** (sets
  `model_artifact.kill_switch_tripped = True`). It **only ever sets** the flag — it has no
  branch that clears it — so a good evaluation on an already-tripped model leaves it
  tripped. Returns the current tripped state.
- **`is_tripped(session, model_version) -> bool`** — reads the **persisted** flag live (it
  survives restarts; drift memory is not in RAM).
- **`rearm(session, model_version, *, operator_confirmed: bool) -> None`** — the **only**
  path that clears the flag, and it raises `ManualReArmRequired` unless
  `operator_confirmed is True`. The prediction/serving pipeline never calls it.
- **`ManualReArmRequired(Exception)`** — raised on any attempt to re-arm without explicit
  operator confirmation.

**Un-trip has exactly one door, and a machine cannot open it.** The evaluation path can
only trip; the serving path only reads; the sole clear is `rearm` behind an explicit
operator flag. There is no automatic recovery.

## Written safety argument (why it cannot silently re-arm) [SAFETY]
1. **Evaluation is monotone toward safety.** `evaluate_kill_switch` sets the flag when
   drift is detected and does nothing when performance is fine — it never clears. So no
   sequence of good runs, however long, can un-trip a switch that has tripped.
2. **The only clear is explicit and human.** `rearm` is the single function that writes
   `kill_switch_tripped = False`, and it raises `ManualReArmRequired` unless the caller
   passes `operator_confirmed=True`. There is no default, no env var, no config flag — the
   operator must act deliberately.
3. **State is persisted, not remembered.** The flag lives on `model_artifact`, so a
   restart cannot "forget" a trip and come up armed. Drift memory outlives the process.
4. **Fail-safe direction.** A tripped switch suppresses ML and shows the baseline — the
   causal, ML-free fallback. The failure mode is *less* automation, never more; the worst
   case degrades to the clinical arithmetic she already relies on.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_kill_switch.py`:
- **Drift trips it:** `should_trip(rolling=0.4, baseline=0.5)` is `True`; `0.6 vs 0.5` is
  `False`. `evaluate_kill_switch` on a drifting model sets the persisted flag; `is_tripped`
  reads `True`; the baseline is the fallback.
- **★ A later good run does NOT re-arm it:** trip the switch, then run
  `evaluate_kill_switch` with `rolling > baseline` (a good run) — `is_tripped` **stays
  True**. Evaluation only trips, never clears.
- **★ Re-arming is manual only:** `rearm(..., operator_confirmed=False)` raises
  `ManualReArmRequired` and leaves it tripped; `rearm(..., operator_confirmed=True)` clears
  it (`is_tripped` becomes `False`). No non-manual path clears it.
- **Persisted / live:** the flag is read from `model_artifact`, so a fresh read after a
  trip still reports tripped.

**RED evidence:** `prescribe/kill_switch.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the tempting "recovery" refactor is to auto-clear the switch when
performance recovers — convenient, and exactly the silent un-trip that puts a drifted
model back in front of someone who cannot feel a low. The "good run does not re-arm" and
"manual only" tests make automatic recovery impossible to add without failing them.
