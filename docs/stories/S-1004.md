# S-1004 [SAFETY] — Synthetic-data generator

**Epic:** 10 (Integration, UI & End-to-End Validation) · **Safety story:** Yes — reclassified on
review (DL-034) · **Status:** In progress · **Requirements:** REQ-056 · **Blocks:** S-1005 (the
end-to-end cycle test consumes this) · **Rollback baseline:** `7a7c3bf` (`v1.0.0-epic9`)

> **Why a data generator is a safety story.** It manufactures records that look exactly like
> hers. The failure mode is not a crash — it is a synthetic row reaching a real model fit, or a
> synthetic number being read as a real reading. Both are silent. So the guard against that is
> structural (a forbidden-import test) rather than a convention, and this story carries a
> written argument.

## Story
A **seeded, reproducible** generator that produces a full synthetic logging cycle — meals with
macros, boluses, basal, exercise, post-meal readings, hypo rescues, correction events — honouring
**reported-timestamp discipline** (ADR-8) and yielding a realistic **hypo minority**, so S-1005
can drive the whole chain and the UI stories have something to render.

## Requirement source
- **REQ-056** — seeded generator for tests/demos, ADR-8 timestamps, **never used on, imported
  by, or presented as, real patient data.**
- **`09-test-plan §2.2`** — seeded/reproducible; no generated clinical `datetime` from the system
  clock; a `tests/forbidden/` guard asserts production packages do not import it.

## Design

### ★ Deviation from the story text — placement (BA decision, record in DL)
The backlog says *"lives under `tests/` / `scripts/` fixtures."* **It will instead live in a new
top-level package `synthetic/`.** Two reasons, both process-level:

1. **Role separation.** `tests/` is SDET's, absolutely (CLAUDE.md). A generator under `tests/`
   would be written *and* tested by SDET — self-marking homework, precisely what the RED-first
   loop exists to prevent. As a top-level package it is **Dev-owned and SDET-tested**, so the
   loop holds.
2. **`scripts/` must not import from `tests/`.** The demo already exists and will consume the
   generator; a script importing a test package is a smell that invites `tests/` onto the
   production path — the opposite of this story's point.

The safety property is **unchanged and still structural**: the forbidden-import guard asserts no
production package imports `synthetic`. `synthetic/` joins the `mypy --strict` scope; it is
**not** added to the coverage gate (it is fixture code, covered by its own tests).

### Module: `synthetic/generator.py`
- **`SyntheticDay` / `SyntheticMeal`** — plain frozen dataclasses mirroring the `meal_event`
  fields the pipeline actually reads (they are **not** ORM rows; persisting is the caller's job,
  so the generator itself can never write to a database).
- **`generate(*, seed: int, days: int, start: dt.date, ...) -> SyntheticDataset`** — the single
  entry point. Everything random derives from `random.Random(seed)`; **no module-level RNG, no
  `random.seed()`, no clock read anywhere.**
- **Timestamps (ADR-8).** Every clinical time (`datetime`, `pre_bg_time`, `post_bg_time`, bolus
  times) is derived from the caller-supplied `start` date plus deterministic offsets.
  **`logged_at` is generated separately, deliberately later than `datetime`** (a plausible
  transcription lag), because the whole point of ADR-8 is that those two differ — a generator
  that set them equal would produce data on which the ADR-8 bug is undetectable.
- **Hypo minority.** Exercise and over-correction drive a realistic ~10–20 % hypo rate; a
  configurable `hypo_rate_target` is *not* offered, because forcing the rate would let a caller
  manufacture whatever result they want to see.
- **Rescues.** A share of hypo meals carry `hypo_treatment=True` + grams, so INV-7 has something
  to exercise end-to-end (S-1005 asserts they are excluded from training yet retained as hypo
  events).

### Guard: `tests/forbidden/` — `detect_synthetic_import`
Follows the S-105 pattern exactly (`_SOURCE_PACKAGES` AST walk): fails if `core/`, `features/`,
`models/`, `prescribe/`, `data/`, `api/`, or `cli/` imports `synthetic` in any form
(`import synthetic`, `from synthetic import …`, `from synthetic.generator import …`).

## Written safety argument [SAFETY]

**The hazard.** Synthetic rows are indistinguishable from real ones by inspection — same fields,
same plausible values. Two failure modes follow, both silent:
(a) a synthetic row is fitted as if it were hers, so the model learns a physiology that is
partly invented; (b) a synthetic number is displayed as a real reading.

**Why the guard is structural, not a convention.** A comment saying *"don't use this in
production"* fails the moment someone is in a hurry. An AST test over every production package
fails the **build**. It is the same lineage as S-105's `datetime.now()` guard: cheap, and it will
fire.

**Why the generator cannot write to a database.** It returns plain dataclasses and holds no
`Session`, no engine, and no import from `data.db`. To get synthetic rows into a database a
caller must persist them deliberately — there is no path where merely *calling* the generator
contaminates a store.

**Why `logged_at ≠ datetime` is required, not cosmetic.** ADR-8 is the project's defining risk:
conflating log time with event time corrupts `bolus_offset_min` and `elapsed_min` with no error
and no post-hoc detection. If the generator set them equal, an S-1005 run would pass whether or
not the production code respects the distinction — the test would be blind to the very bug it
exists to catch. So the generator emits a deliberate lag, and SDET asserts it.

**Why there is no `hypo_rate_target` knob.** A caller who can dial the hypo rate can dial the
headline metric. The rate must **emerge** from the simulated physiology (carbs, insulin,
exercise) so that a model evaluated on it is being evaluated on something it did not choose.

**What this story does not claim.** Synthetic data proves *wiring*, never *clinical validity*.
Nothing here shortens the 150-meal or 90-day requirements, and no metric computed on synthetic
data may ever be quoted as evidence about the real model. S-1005 asserts plumbing; Gate 1 still
demands real meals.

## TDD strategy (SDET first — written and seen to fail before Dev implements)
`tests/unit/test_synthetic.py`:
- **★ Determinism:** the same seed twice ⇒ **byte-identical** output (compared as a serialised
  digest, not field-by-field — a field-by-field check would silently miss a new field).
- **★ Different seeds differ** — otherwise "deterministic" could be satisfied by a constant.
- **★ ADR-8:** for every generated meal, `logged_at > datetime` **and** they are never equal;
  `elapsed_min` is consistent with `post_bg_time − datetime`, computed from **reported** times.
- **★ No clock read:** an AST scan of `synthetic/` finds no `datetime.now`/`today`/`utcnow` and
  no bare `random.` module-level call — the generator's only entropy source is the injected seed.
- **Shape:** the requested number of days is produced; 2–3 meals/day; `bolus_offset_min` is
  present on every meal and takes both signs; macros are non-negative; `net_carbs ≥ 0`.
- **Hypo minority is real and emergent:** a long run yields a hypo rate strictly between 0 and
  0.5 (not zero — otherwise INV-7 and hypo recall are untestable; not a majority — that is not
  her life). **No knob is asserted, because none exists.**
- **Rescues exist** and every rescued meal carries `hypo_treatment_g > 0`.

`tests/forbidden/test_forbidden_patterns.py`:
- **★ `detect_synthetic_import` fires** on a synthetic source string that imports it (proving the
  guard bites), **and** is clean across the real production packages.

**RED evidence:** `synthetic/` does not exist; every import fails; `detect_synthetic_import` is
undefined.

**Adversarial angle.** The temptations here are (a) seeding from the clock "so runs vary" — which
destroys reproducibility and quietly re-introduces the ADR-8 hazard; (b) setting
`logged_at = datetime` for convenience, which blinds the E2E test to the project's defining bug;
and (c) adding a hypo-rate knob, which turns the E2E suite into a machine for producing whatever
number the operator hoped for. All three are cheap to write and expensive to detect later, so
each has a test.
