# S-801 [SAFETY] — Output guardrails

**Epic:** 8 (Guardrails & Output) — **opens EPIC 8** · **Safety story:** Yes ·
**Status:** In progress · **Requirements:** REQ-044, REQ-046, **INV-6**

> **A guess is worse than a refusal, and infinitely more dangerous to someone who cannot
> feel a low.** When the model is out of its depth — an unseen meal, a thin data region,
> a posterior that can't commit, a disagreement with the baseline, or an impossible
> number — the correct output is **not a state**. It is a refusal, a flagged conflict, or
> a hard error. This story is the layer that refuses to fill the silence with a number.

## Story
Wrap the raw prediction in a guardrail that evaluates five conditions and, if any fire,
does **not** return a bare state: **out-of-distribution** and **sparse-region** and a
**diffuse posterior (no state > 40%)** all **refuse**; a **baseline conflict** (baseline
and model more than one state apart) returns **both, flagged, with no winner picked**; a
**physiologically absurd** predicted BG (outside [20, 600]) is a **hard error** (INV-6).

## Requirement source
- **REQ-044 / INV-6** — predicted BG outside [20, 600] raises a hard error.
- **REQ-046 / 07 §10** — output guardrails: OOD, sparse region, diffuse posterior,
  baseline conflict. *"Refuse to predict if ANY fire. A refusal is a valid, correct
  output. Never fill the silence with a number."*
- **08 scenarios** — no state > 40% ⇒ *"Not confident enough to predict this one"*, returns
  NO number; more carbs than any in training ⇒ refuse; baseline State 3 vs model State 5 ⇒
  **both shown, flagged, no winner**; predicted 620 ⇒ `SafetyViolation` (INV-6).

## Design
`models/guardrails.py` (pure — imports only `core.safety` for INV-6):

- `CONFIDENCE_THRESHOLD = 0.40` — a state must **exceed** 40% to be predicted.
- `SPARSE_MIN_NEIGHBORS = 10` — fewer than ~10 nearby training meals ⇒ refuse.
- `RefusalReason(str, Enum)` — `OUT_OF_DISTRIBUTION`, `SPARSE_REGION`,
  `DIFFUSE_POSTERIOR`; `REFUSAL_MESSAGES` maps each to plain-language text
  (diffuse ⇒ *"Not confident enough to predict this one"*).
- `GuardedPrediction` — `refused: bool`, `reason: RefusalReason | None`,
  `state: int | None` (only when confident **and** no conflict), `max_confidence`,
  `conflict: bool`, `model_state`, `baseline_state`, `message`.
- **`guard_prediction(*, proba, states, predicted_bg, baseline_state, in_distribution,
  n_nearby_train) -> GuardedPrediction`** — evaluation order:
  1. **Absurd (INV-6, always first):** `inv6_predicted_bg_in_range(predicted_bg)` — raises
     `SafetyViolation` when outside [20, 600]. A hard error, not a refusal.
  2. **Out of distribution:** `not in_distribution` ⇒ refuse (`OUT_OF_DISTRIBUTION`).
  3. **Sparse region:** `n_nearby_train < 10` ⇒ refuse (`SPARSE_REGION`).
  4. **Diffuse posterior:** `max(proba) ≤ 0.40` ⇒ refuse (`DIFFUSE_POSTERIOR`, "not
     confident"). `0.39 ⇒ refuse`, `0.41 ⇒ a state`.
  5. **Baseline conflict:** `|model_state − baseline_state| > 1` ⇒ **not** refused, but
     `conflict = True`, both states carried, `state = None` (**no winner picked**).
  - Otherwise: a confident, agreeing prediction — `state = model_state`.

**Refusal is a first-class output, not an exception** (except the absurd case, which must
be a loud hard error). The patient readout (S-804) renders a refusal as a state of its
own — never a blank, never a guessed number.

## Written safety argument (why a low can't slip through as a guess) [SAFETY]
1. **The absurd case is loud, not swallowed.** INV-6 is evaluated first and raises; an
   impossible BG can never be dressed up as a refusal message or a state — it stops the
   pipeline.
2. **Every uncertainty path returns "no number".** OOD, sparse, and diffuse each return a
   `refused=True` `GuardedPrediction` with `state = None`. There is no branch that, under
   uncertainty, emits a bare state — the silence is filled with a refusal, never a guess.
3. **Disagreement is surfaced, not arbitrated.** When the baseline and model diverge by
   more than one state, the guard sets `conflict = True`, carries **both**, and leaves
   `state = None`. It does not pick a winner — the human sees the disagreement, which is
   the honest signal precisely when the model might be wrong about a low.
4. **The threshold is strict.** A state must *exceed* 40% to be emitted; a posterior
   sitting exactly at the line refuses. Confidence is earned, not rounded up to.

## TDD strategy (SDET, written first — seen to fail)
`tests/safety/test_guardrails.py` — one triggering test per condition:
- **OOD refuses:** `in_distribution=False` ⇒ `refused`, reason `OUT_OF_DISTRIBUTION`,
  `state is None`.
- **Sparse refuses:** `n_nearby_train=9` ⇒ `refused`, `SPARSE_REGION`; `10` does not.
- **★ Diffuse boundary:** `max(proba)=0.39` ⇒ refused, `DIFFUSE_POSTERIOR`, message
  contains "confident", `state is None`; `max(proba)=0.41` ⇒ **not** refused, `state`
  set.
- **★ Baseline conflict shows both:** baseline State 3, model State 5 ⇒ `refused=False`,
  `conflict=True`, `model_state=5`, `baseline_state=3`, **`state is None`** (no winner);
  a one-apart difference (3 vs 4) is **not** a conflict.
- **★ Absurd is a hard error:** `predicted_bg=601` ⇒ `SafetyViolation` (INV-6);
  `predicted_bg=600` ⇒ does **not** raise; `20` ok, `19` raises.
- **Clean path:** in-distribution, dense, confident (0.8), agreeing ⇒ `state` set,
  `refused=False`, `conflict=False`.

**RED evidence:** `models/guardrails.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the trap is to always return the arg-max state "so the UI has
something to show." That is the guess that kills. These tests make every low-confidence,
out-of-range, or conflicting case resolve to a refusal or a flagged both-shown output with
`state is None`, so the arg-max shortcut cannot survive.
