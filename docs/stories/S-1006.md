# S-1006 [SAFETY] — Gate-1 manual promotion

**Epic:** 10 · **Safety story:** Yes — it **tightens** INV-2 · **Status:** In progress ·
**Requirements:** REQ-058, **INV-2** · **Record:** DL-034 (the review that found the gap) ·
**Rollback baseline:** `7a7c3bf`

> **This is conformance work, not new scope.** `07 §Retraining` has always said *"Promotion is
> manual, on hypo recall."* `03 §3` has always listed manual promotion as a Gate-1 condition.
> The **code** has been opening Gate 1 on metrics alone, and `ModelArtifact.is_promoted` —
> commented *"manual only"* — has sat unread since S-201. This story makes the code match the
> spec it already had.

## Story
`gate1_status()` gains a **required** `is_promoted` input and opens **only** when
`volume ∧ beats_baseline ∧ is_promoted`. Promotion becomes an explicit, audited operator action.

## The distinction that matters
S-1008 already reads `is_promoted` to answer **"which model serves?"**. This story makes Gate 1
*require* it, answering **"may she see it?"** — the same flag, two different questions. A model
can legitimately serve into the shadow log while remaining invisible to her; that is exactly
what shadow mode is.

## Design

### `prescribe/gates.py`
- `gate1_status(*, valid_meals, model_hypo_recall, baseline_hypo_recall, is_promoted)` —
  **`is_promoted` is required, not defaulted.** A default of `False` would be safe-by-accident
  but would let a caller silently omit it; a default of `True` would be a disaster. Requiring it
  forces every call site to state its answer, and makes the compiler find the ones that don't.
- `Gate1Status` gains `is_promoted: bool` so the operator dashboard can render *which* condition
  is blocking (S-1001 needs this — a disabled button with no reason is a dead control).

### `data/promotion.py` — the audited action
- **`promote_model(session, version, *, confirmed_by) -> ModelArtifact`** — sets `is_promoted`
  and writes an `audit_log` row (who, when, old→new). Refuses an unknown version.
- **`revoke_promotion(session, version, *, confirmed_by)` —** the same, in reverse. Revocation
  must be as easy as promotion; a gate you cannot shut is not a gate.
- **Exactly one artifact may be promoted at a time.** Promoting a new version demotes the
  incumbent *in the same transaction*, so `get_promoted_artifact` can never face an ambiguous
  "which one?" — and the demotion is audited too.

## Written safety argument [SAFETY]

**What this closes.** Before this story, every automatic condition passing was *sufficient*:
the moment hypo recall crossed the baseline on ≥150 meals, Gate 1 opened and she would have
started seeing model output — with no human ever deciding that she should. The most dangerous
version of this system is not one that crashes; it is one that starts being trusted without
anyone choosing to trust it. This makes that choice explicit and attributable.

**Why `is_promoted` is required rather than defaulted.** A default is a decision made once, by
the author, on behalf of every future call site. `False` would be "safe" but would let a caller
forget the question entirely and still compile — and the next person to add a call site would
never learn the condition exists. Making it required converts a silent omission into a type
error at every site.

**Why promotion is audited, not just recorded.** `is_promoted` alone answers *what*; the audit
row answers *who, when, and from what*. If she is ever shown something wrong, "when did this
become visible and who decided" must be answerable from the database, not from memory.

**Why one-promoted-at-a-time is enforced in the same transaction.** Two promoted artifacts is an
ambiguous state with no correct answer — `get_promoted_artifact` would return whichever the
query happened to order first, and the served model would depend on row order. Demoting the
incumbent atomically means that state cannot exist, rather than being merely unlikely.

**Fails closed, everywhere.** No promoted row ⇒ not promoted. Unknown version ⇒ refuse, don't
create. Absent flag ⇒ `False`. Every ambiguity resolves toward *she does not see it*.

**What this does not do.** It does not decide *when* to promote — that stays with the operator
and the endocrinologist. It adds no automatic path, and it deliberately does not read a config
value or environment variable, because either would be a way to promote without a person.

## TDD strategy (SDET first — written and seen to fail)
`tests/safety/test_gates.py` (extends the existing Gate-1 suite, which stays):
- **★ THE MISSING CASE:** volume ✓ **and** beats-baseline ✓ **and not promoted ⇒ CLOSED.**
  This is precisely the case the shipped code got wrong.
- **★ Promoted alone is never sufficient:** promoted ✓ but 149 meals ⇒ closed; promoted ✓ but
  recall ≤ baseline ⇒ closed; a tie ⇒ closed. Promotion is the **last** condition, not a bypass.
- **★ `is_promoted` is required** — calling `gate1_status` without it raises `TypeError`. Pins
  that a future refactor cannot re-introduce a default and quietly restore the old behaviour.
- **No env var promotes**: bypass-looking variables set ⇒ still closed.
- `Gate1Status` exposes `is_promoted` so a UI can name the blocking condition.

`tests/integration/test_promotion.py`:
- `promote_model` sets the flag **and** writes an audit row (old→new, `changed_by`).
- **★ Promoting v2 demotes v1 atomically** ⇒ `get_promoted_artifact` is unambiguous, and **both**
  changes are audited.
- `revoke_promotion` clears it and audits; a revoked model stops serving on the next call
  (gates are live, ADR-7).
- Unknown version ⇒ raises, and **no** row is created.
- **★ Grep/AST: no production module sets `is_promoted` outside `data/promotion.py`** — the
  "auto-promote once metrics pass" temptation the story names.

**RED evidence:** `gate1_status` currently accepts three arguments and opens without promotion;
`data/promotion.py` does not exist.

**Adversarial angle.** The tempting shortcut is auto-promotion once metrics pass — it looks like
progress and it is exactly what `07 §Retraining` forbids. The second temptation is defaulting
`is_promoted=True` "so the tests pass", which would restore the bug while looking like a fix.
Both are covered.
