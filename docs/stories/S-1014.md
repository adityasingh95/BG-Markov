# S-1014 — Persist the fitted model on the artifact

**Epic:** 11 (post-EPIC-10 wiring) · **Safety story:** No — but it is what makes promotion
mean anything · **Status:** In progress · **Requirements:** REQ-059, REQ-060 ·
**Records:** **DL-052** (parameters not pickle; the scaling correction) · **Blocks:** S-1015 ·
**Rollback baseline:** `256850b`

> `ModelArtifact` stores a manifest — version, hash, row count, feature list, metrics — and
> **no coefficients.** `run_refit` fits a model, scores it, and discards the fit. Promoting an
> artifact today promotes a *record of* a model, not a model: there is nothing to load and
> nothing to serve.

## Story
A refit stores the fitted model's parameters on the artifact, and a promoted artifact can be
loaded back into something that produces probabilities.

## Why this blocks everything downstream

`prescribe/serving.py::serve_meal_prediction` has existed since S-1008 and takes a
`_ProbabilityModel` — an object with `predict_proba`. Nothing can supply one from the
database. So:

- no prediction can be served in the running app (S-1015 depends on this),
- `prediction_log` stays empty,
- shadow evidence never accrues,
- the 90-day clock never starts,
- **Gate 1 can never open.**

Same family as DL-046 and DL-049: components correct and unconnected. This one is the last
link in that chain.

---

## ★ A defect found while scoping: the metrics describe a different model

`run_refit` scores through `temporal_cv`, which **scales** each fold (`scale=True`, S-404 —
the scaler is fit on train rows only, which is right). The final full-window fit is then done
on **raw, unscaled** features.

So the coefficients that would be persisted come from a model fitted on one representation,
and the `hypo_recall` sitting beside them on the same artifact row was measured on another.
The manifest reads as one coherent object and is not one.

It has been harmless only because nothing ever loaded the model. The moment this story stores
it, the mismatch becomes a served prediction that no measurement describes — and the number
the operator reads on the shadow dashboard would be about a model that was never served.

**Fix:** fit a `StandardScaler` on the full window, fit the final model on the scaled matrix,
and **persist the scaler's `mean_`/`scale_` alongside the coefficients**. Serving then applies
the identical transform. The per-fold scaler inside CV stays exactly as it is — fitting *that*
on the full set would be the leakage S-404 exists to prevent, and the two are different
scalers for different jobs.

## Design

### Storage format: **parameters as JSON, never a pickle**

`model_artifact` gains one nullable JSON column, `fitted_model`.

**Why not pickle**, stated once so it is not re-litigated:
1. **Unpickling executes code.** A model blob becomes an execution vector on a machine that
   holds her clinical record.
2. **It couples behaviour to library versions.** A statsmodels or numpy upgrade can change
   what a pickle deserialises to — or refuse it — and the failure would surface as a *changed
   prediction*, silently, for a model the operator promoted months earlier on evidence
   gathered from different behaviour.
3. **It is unreadable.** An operator, or a future maintainer, cannot answer *"what does this
   model actually do?"* from a binary blob. A coefficient vector with feature names beside it
   is inspectable, diffable, and greppable.

The stored object is small and complete:

```
{"kind": "ordinal_po", "states": [...], "feature_names": [...],
 "params": [...],                 # feature coefs then thresholds, statsmodels order
 "scaler_mean": [...], "scaler_scale": [...]}
```

### `models/ordinal.py` — `OrdinalFit.to_params()` / `ordinal_from_params(...)`
Round-tripping lives **next to the model**, not in the data layer. The statsmodels threshold
parameterisation is an internal detail of this module; a serialiser in `data/` would have to
reach into it, and would then break quietly when statsmodels changed.

`ordinal_from_params` rebuilds a model shell of the right shape and returns something that
satisfies the same `predict_proba` contract.

### `data/model_store.py` — `save_fitted_model` / `load_fitted_model`
The DB boundary. `load_fitted_model` returns `None` for an artifact with no stored model —
**every artifact written before this story** — rather than raising. An old artifact is a real
historical row; the caller serves the baseline, which is what it already does when there is
no promoted model at all.

---

## Why this is not a `[SAFETY]` story

It stores and reloads numbers. It shows nothing to her, computes no dose, and opens no gate:
Gate 1 still requires all five conditions, INV-2 still governs what she sees, and the dose
path still contains no ML at all. What it changes is that **promotion becomes meaningful** —
which raises the stakes of the gate without weakening it.

One real risk is worth naming: a model reloaded *incorrectly* would produce different
probabilities from the one that was scored, and nothing downstream would notice. That is what
the round-trip test below is for, and why it asserts on **probabilities**, not on parameters.

---

## TDD strategy (SDET first — written and seen to fail)

`tests/integration/test_model_store.py`:
- **★ Round-trip fidelity on PROBABILITIES, not parameters.** Fit, save, load, predict on the
  same rows, and require the probabilities to match to `1e-9`. Comparing stored parameter
  vectors would pass while a threshold-ordering or scaling mistake changed every prediction —
  the parameters are not the thing that matters.
- **★ The reloaded model sees the same scaling.** Predict through the loaded model on *raw*
  feature rows and match the original fit's probabilities — a stored scaler that is ignored,
  or applied twice, fails here and nowhere else.
- **★ An artifact from before this story loads as `None`, not an exception.** The column is
  nullable and old rows are real history.
- **★ No pickle anywhere.** An AST/grep guard: `pickle`, `dill`, `joblib` and `marshal` are
  not imported under `models/` or `data/`. Settled by DL-052; the guard is what keeps it
  settled when someone reaches for the one-line version.
- A refit writes a non-null `fitted_model`, and it names the same features as `feature_list`.
- **★ The scored metrics and the stored model come from the same representation** — assert
  the final fit is done on the scaled matrix, by checking that a refit on data with a
  deliberately large-scale feature stores a scaler whose `scale_` is not all ones.

**RED evidence:** `model_artifact.fitted_model` does not exist; `data.model_store` does not
exist; `OrdinalFit.to_params` does not exist.

**Adversarial angle.** Three. (a) **Pickle**, because it is one line and round-trips
everything. (b) **Storing the parameters but not the scaler** — the round trip passes on
scaled inputs and every real prediction is wrong. (c) **Comparing parameters instead of
probabilities** in the round-trip test, which is the version of the test that looks rigorous
and proves nothing.
