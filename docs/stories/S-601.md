# S-601 — Ordinal model (the one model)

**Epic:** 6 (The Model) — **opens EPIC 6** · **Safety story:** No (but INV-6/INV-8
adjacent) · **Status:** In progress · **Requirements:** REQ-031

> **The states are ordered, and the ordering is the whole point.** Predicting State 4
> when the truth is State 1 is catastrophic; predicting State 3 when the truth is
> State 4 is a minor error. A multinomial model treats those two mistakes as equally
> wrong — it is the wrong model class. This story fits **one** proportional-odds
> ordinal logit, with `pre_bg` continuous, L2 regularisation, and the hypo states
> up-weighted (multiplicatively with the macro-confidence weights) because they are
> rare and they are the ones that matter.

## Story
Fit a single ordinal logistic regression (proportional odds, `distr="logit"`) over
the feature matrix with `pre_bg` **continuous**; L2-penalise the feature
coefficients; weight each observation by `hypo_weight (if state ∈ {1,2}) ×
macro_confidence`. Expose `predict_proba` (rows sum to 1) and a `P(state ≥ k)`
accessor for the ordinal-monotonicity and downstream risk read-outs.

## Requirement source
- **REQ-031** — the prediction model is one ordinal logistic regression.
- **07 §8** — *"Ordinal logistic regression, proportional odds. ONE model. `pre_bg`
  continuous."* `OrderedModel(y_state, X, distr="logit").fit(...)`. Ordinal because
  the states are ordered and off-by-one ≪ off-by-three; **multinomial cannot tell
  those apart.** Class imbalance: *"States 1, 2, 5 are rare and are the ones that
  matter. Up-weight the hypo states. Combine multiplicatively with `macro_confidence`
  weights."*
- **Forbidden (07 §8 / CLAUDE.md):** `LogisticRegression(multi_class='multinomial')`;
  per-state sub-models (`for state in range(1,6): fit(...)`); binning `pre_bg` as an
  **input**.

## Design
`models/ordinal.py` (pure — `models/` holds the estimators):

- `HYPO_STATES = frozenset({1, 2})`, `DEFAULT_HYPO_WEIGHT = 4.0`,
  `DEFAULT_L2_ALPHA = 1.0`.
- `hypo_confidence_weights(y_state, confidence_weights, *, hypo_weight) -> ndarray` —
  the **multiplicative** combination: `confidence × (hypo_weight where state ∈ {1,2}
  else 1.0)`. Pure; independently tested.
- `fit_ordinal(X, y_state, *, confidence_weights, hypo_weight=DEFAULT_HYPO_WEIGHT,
  l2_alpha=DEFAULT_L2_ALPHA) -> OrdinalFit` — builds the combined weights, fits **one**
  `_WeightedL2OrderedModel` (a thin `OrderedModel` subclass: weighted `loglikeobs`,
  and `loglike = Σ wᵢ·llᵢ − l2_alpha·‖β_features‖²` — ridge on the **feature**
  coefficients only, never the thresholds). `distr="logit"`, `method="bfgs"` (see
  deviation), `maxiter=2000`.
- `OrdinalFit` carries the fitted model + params and `states` — the **observed**
  ordered states, i.e. the meaning of each `predict_proba` column.
  - `predict_proba(X) -> ndarray (n, len(states))` — rows sum to 1.
  - `prob_at_least(X, state) -> ndarray` — `Σ` of the columns whose state `≥ state`;
    this is the monotone quantity (`P(state ≥ 4)` rises with `pre_bg`).

**One model, not five.** `pre_bg` enters continuously and is never binned as an
input; the binner (`models/state.py`) only ever touches an **output** BG. The
proportional-odds structure means `P(state ≥ k) = logistic(β·x − τ_{k-1})`, so with a
positive fitted `β_pre_bg` the survival curve is monotone in `pre_bg` for **every**
threshold — the ordinal-sanity property is structural, not coincidental.

### Deviation — `method="lbfgs"` → `method="bfgs"` (decision-log DL-025)
07 §8 writes `.fit(method="lbfgs", …)`. Under the pinned toolchain
(`statsmodels==0.14.4` + `scipy==1.18.0`) that call raises
`TypeError: fmin_l_bfgs_b() got an unexpected keyword argument 'disp'` — a
statsmodels/scipy incompatibility, **not** a modelling choice. `method="bfgs"` is the
same maximum-likelihood objective by a different quasi-Newton step; it converges to
the same optimum (probabilities sum to 1, monotonicity holds). Recorded as DL-025 so
a later reader does not "restore" the spec's `lbfgs` and re-break the build.

### Absent-class hazard (deferred to wiring/gate — flagged, not silently handled)
On a tiny single-patient training fold a state may be **entirely unobserved**. Forcing
all five categories then makes the missing threshold unidentifiable (the fit diverges
and the probabilities stop summing to 1). `fit_ordinal` therefore models the
**observed** ordered states and reports them via `OrdinalFit.states` — it does **not**
fabricate a zero-probability column for an unobserved state. Assigning `P = 0` to an
unseen **hypo** state would silently assert "this low cannot happen", which is exactly
the failure this whole system exists to make loud. Mapping onto the full 5-vector, and
the refusal that must accompany a missing hypo class, belong to the gate/risk-readout
stories (S-703 / S-804) — this story stops at the honest estimator. See DL-025.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_ordinal.py` (synthetic data spanning all five states, generated as a
monotone latent function of `pre_bg` + carbs so the ordering is real):

- **Probabilities sum to 1.** `predict_proba(X)` rows sum to 1.0 for every row.
- **★ Ordinal sanity:** over a `pre_bg` grid (carbs held at the mean),
  `prob_at_least(·, 4)` = `P(state ≥ 4)` is **non-decreasing** — the defining property
  of a correct ordinal fit.
- **Multiplicative weights:** `hypo_confidence_weights([1,2,3,4,5], [0.5]*5,
  hypo_weight=4)` == `[2,2,0.5,0.5,0.5]` — hypo states up-weighted **× confidence**.
- **L2 shrinks:** `‖β_features‖` at a large `l2_alpha` is strictly smaller than at
  `l2_alpha=0`.
- **One model / five states:** a single `OrdinalFit` is returned and its `states`
  cover all five on full-range data (no per-state sub-models).
- **Forbidden greps stay green:** `multi_class` absent, no `for state in range(1,6):
  fit(...)`, no `accuracy_score` — the existing AST guards in
  `tests/forbidden/` cover the new module (it lives under the scanned tree).

**RED evidence:** `models/ordinal.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the trap is reaching for `LogisticRegression` (a multinomial
classifier) because it is familiar — which discards the ordering and rates an
off-by-three no worse than an off-by-one. The ordinal-sanity test is the tripwire: a
multinomial fit has no reason to keep `P(state ≥ 4)` monotone in `pre_bg`, so it would
fail this test even before the forbidden-pattern grep caught the import.
