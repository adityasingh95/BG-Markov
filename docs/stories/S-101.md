# S-101 — Project skeleton

**Epic:** 1 (Foundation) · **Safety story:** No · **Status:** Done (see caveat DL-002)

## Story
Stand up the project so that every later story runs inside a toolchain that
*enforces* its guarantees. This story ships no clinical behaviour — it ships the
gates (lint, types, tests, coverage) that make the forbidden-pattern suite
(S-105) and every `[SAFETY]` story meaningful.

## Acceptance criteria
- [x] `pytest`, `ruff`, `mypy --strict` clean.
- [x] Coverage gate at 90% on `core/` — configured in `pyproject.toml`
      (`[tool.coverage] fail_under = 90`) and enforced in CI. See DL-002.
- [x] Deps pinned: fastapi, statsmodels, pandas, pydantic, hypothesis, alembic
      (plus uvicorn, jinja2, sqlalchemy, pydantic-settings; dev: pytest,
      pytest-cov, coverage, ruff, mypy).

## REQs / INVs touched
- **REQs:** none directly (infrastructure story).
- **INVs:** none directly. Establishes the enforcement machinery that S-104
  (INV-1..9) and S-105 (forbidden patterns) depend on.

## TDD strategy (SDET, written first — seen to fail)
Floor from backlog: *CI fails on a deliberate lint error; fails on a deliberate
type error.* Expanded to:

1. `test_ruff_fails_on_deliberate_lint_error` — an unused import makes
   `ruff check` non-zero. **The lint gate must bite.**
2. `test_mypy_fails_on_deliberate_type_error` — a type error makes
   `mypy --strict` non-zero. **The type gate must bite.**
3. `test_ruff_clean_on_project` — the committed skeleton is ruff-clean.
4. `test_mypy_strict_clean_on_core` — `core/` is `mypy --strict` clean.
5. `test_core_exposes_version` — gives the 90% coverage gate real code to
   measure rather than passing vacuously on an empty package.

**RED evidence:** commit `test(S-101): RED …` — tests 4 and 5 fail (no `core`
code yet); tests 1–2 pass because they assert the tools' failure behaviour,
which is independent of our code.

**Adversarial angle:** a gate that does not fail on a defect is worse than no
gate — it certifies broken code as clean. Tests 1–2 exist so a future change
that misconfigures ruff/mypy (e.g. disabling rules, dropping `--strict`) turns
the suite red instead of silently green.

## What was built
- `pyproject.toml` — pinned deps, ruff (`E,F,I,UP,B,SIM`, line-length 100),
  mypy strict, pytest, coverage (branch, source=`core`, fail_under=90).
- `core/` package with `__version__`.
- `.github/workflows/ci.yml` — ruff → mypy → pytest+coverage.
- `.gitignore` — excludes `.venv`, tool caches, and (critically) `*.db` /
  `export-*.csv` so patient data can never be committed.
