# S-104 [SAFETY] — Safety invariants module

**Epic:** 1 (Foundation) · **Safety story:** Yes · **Status:** Done

## Story
Implement INV-1..9 as the single, dependency-free source of every safety
invariant in the system. Each invariant is **one named function** in
`core/safety.py`. Each **raises `SafetyViolation`** (never `assert` — asserts are
stripped under `python -O`). The module **imports nothing from the project**
(ADR-6) so no later refactor can create a circular dependency that quietly
weakens it. Every other module *calls* these functions; none re-implements them.

This story does not wire the invariants into features (that happens per later
story). It ships the invariants themselves plus the static guarantees that keep
them un-weakenable.

## Exception hierarchy
```
SafetyViolation(Exception)          # base — INV-3, INV-4, INV-5, INV-6, INV-7, INV-8, INV-9
└── GateNotPassed(SafetyViolation)  # INV-1, INV-2 → 403 GATE_NOT_PASSED
```
`GateNotPassed` is-a `SafetyViolation`, so "invariants raise `SafetyViolation`"
holds for every one of them. INV-6 raises the base class (`08` scenario:
*"a SafetyViolation is raised"*). INV-4's raise is translated to
`BG_TOO_LOW_FOR_BOLUS` by its caller (S-901), which knows it invoked INV-4.

## Invariant functions (signatures — dependency-free primitives, ADR-6)
| INV | Function | Raises when |
|---|---|---|
| 1 | `inv1_prescriptive_requires_gate2(gate2_passed: bool)` | `not gate2_passed` → `GateNotPassed` |
| 2 | `inv2_patient_output_requires_gate1(gate1_passed: bool)` | `not gate1_passed` → `GateNotPassed` |
| 3 | `inv3_bolus_within_bounds(dose_u: float)` | `dose_u < 0` or `dose_u > MAX_BOLUS_U (15)` |
| 4 | `inv4_bolus_allowed_at_bg(current_bg: float)` | `current_bg < BOLUS_BG_FLOOR (80)` |
| 5 | `inv5_monitoring_not_reduced(current_tests_per_day, recommended_tests_per_day)` | `recommended < current` |
| 6 | `inv6_predicted_bg_in_range(predicted_bg: float)` | outside `[20, 600]` |
| 7 | `inv7_rescued_excluded_and_retained(training_ids, hypo_ids, rescued_ids)` | a rescued id is in training, **or** missing from hypo events |
| 8 | `inv8_beta_insulin_non_negative(beta_insulin: float)` | `beta_insulin < 0` |
| 9 | `inv9_prediction_persisted(prediction_id: int \| None)` | `prediction_id is None` |

Constants live here and are the **single source**: `MAX_BOLUS_U = 15.0`,
`BOLUS_BG_FLOOR = 80.0`, `PREDICTED_BG_MIN = 20.0`, `PREDICTED_BG_MAX = 600.0`.
None takes a `force`/`skip`/`bypass` parameter (adversarial test asserts this).

## Written invariant argument (why the module is safe) [SAFETY]
1. **One function each, one file.** Every invariant is defined exactly once. A
   grep/AST test fails the build if an `inv<n>` function or a re-declaration of
   `SafetyViolation` appears anywhere but `core/safety.py`. There is no second
   copy to drift out of sync (CLAUDE.md rule 1).
2. **Raise, never `assert`.** `python -O` strips `assert`, which would silently
   disable every check in production. A static AST test proves no `assert` node
   exists in the module, and a behavioural test runs a negative case under
   `python -O` and confirms it still raises (CLAUDE.md rule 2).
3. **Zero internal imports (ADR-6).** An AST test proves the module imports only
   stdlib/typing. Nothing in `core/features/models/...` can be imported here, so
   no import cycle can be introduced that lets a downstream module monkey-patch
   or shadow an invariant into a weaker form (CLAUDE.md rule 3).
4. **No bypass (rule 4).** The functions take only the data they check — no
   config flag, no env var, no `force=` kwarg. An adversarial test sets
   plausible bypass env vars (`BYPASS_SAFETY`, `DEBUG`, …) and asserts INV-1
   still raises, and inspects each signature for the absence of a skip/override
   parameter.
