# S-302 [SAFETY] — Bolus timing

**Epic:** 3 (Logging & Durability) · **Safety story:** Yes · **Status:** In progress

## Story
`bolus_offset_min` is a **signed** value (negative = pre-bolus) and one of the
two most predictive features. It **cannot be skipped or silently defaulted**. If
a skipped entry quietly became `0` ("with food"), the model would train on a
fabricated pre-bolus timing for every rushed log — silently, with no error.
S-302 makes the choice deliberate at **both** ends: the client refuses to submit
without a timing choice (and never auto-fills `0`), and the server requires the
field (422 if absent) with **no default**.

## Requirement source
- **REQ-003** — `bolus_offset_min` is signed and **cannot be skipped**.

## Acceptance criteria (backlog)
- [ ] Signed offset; **cannot be skipped or silently defaulted**.
- [ ] Submission without a timing choice is **rejected**.
- [ ] "15 min before" ⇒ `-15`.

## Written invariant argument (why this is safe) [SAFETY]
Skipping is prevented at two independent layers, so no single lapse defaults the
value:
1. **Schema (server).** `MealCreate.bolus_offset_min` is a required `int` with
   **no default**. An absent or `null` value is a `422`, never a silent `0`.
   A test asserts the field is required (guards against a future default sneaking
   in).
2. **Form (client).** The offset field is empty until a preset is tapped, a
   before/after direction is applied, or a value is typed. On submit, an **empty**
   offset is **blocked** with an `aria-live` prompt — the POST is not sent. A
   deliberate `0` (from "Just before" / "With food", or typed) is distinguishable
   from *unset* (empty) and is allowed. The client never writes `0` on its own.

The distinction that makes this safe: **empty ≠ 0**. "Unset" is a blockable
state; "with food" is a chosen `0`.

## TDD strategy (SDET, written first — seen to fail)
`tests/integration/test_bolus_timing.py`:
- `POST /api/meals` with `bolus_offset_min: null` ⇒ **422**.
- `MealCreate` has **no default** for `bolus_offset_min` (the field is required).

`tests/e2e/test_bolus_timing.py`:
- **Submit without choosing timing** ⇒ **no confirmation**, and a visible prompt
  to choose timing (the entry is not logged).
- **"15 min before" ⇒ the offset field is `-15`** (the signed mapping).
- Choosing a timing then submitting logs successfully (the positive path).

**RED evidence:** with no client guard and no timing-error element, the block
test fails (a meal without timing would either post or show no prompt).

**Adversarial angle:** the tempting "just default it to 0 so the form always
submits" is exactly the silent corruption this story exists to prevent. The
empty-is-blocked test catches it.
