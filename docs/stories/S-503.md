# S-503 [SAFETY] — ★ ICR/ISF constrained OLS (INV-8)

**Epic:** 5 (Baseline & Parameters) — **closes EPIC 5** · **Safety story:** Yes,
the central one · **Status:** In progress · **Requirements:** REQ-032, **INV-8**

> **Confounding by indication is the central hazard.** Bolus is chosen *in response
> to* carbs and pre-meal BG, so in observational data higher insulin correlates with
> higher post-meal glucose — a naive fit learns that insulin **raises** glucose. The
> correlation is real; inverting it into dosing advice is a hypo pathway. This story
> is the guard: `β_insulin` is sign-constrained ≥ 0 in every fit, an unconstrained
> negative coefficient is **reported** (not swallowed), and the result is
> cross-checked against the unconfounded correction events.

## Story
Fit ICR/ISF from the training set with **sign-constrained OLS** (`β_carb ≥ 0`,
`β_ins ≥ 0`); if the unconstrained fit wants `β_ins < 0`, log a prominent
confounding-by-indication warning and apply the constraint; cross-check the derived
ISF against the correction-event ISF (S-502) and, on material disagreement, prefer
the correction events.

## Requirement source
- **REQ-032 / INV-8** — `β_insulin` sign-constrained ≥ 0 in **every** fit.
- **07 §7** — `post_bg = pre_bg + β_carb·carbs_g − β_ins·total_bolus + intercept`,
  subject to `β_carb ≥ 0, β_ins ≥ 0`; `ISF = β_ins`, `ICR = ISF/β_carb`; if the
  **unconstrained** fit wants `β_ins < 0`, **log a prominent warning naming
  confounding-by-indication, then constrain** — do not accept the negative
  coefficient; cross-check against correction-event ISF (§6), **prefer the
  correction events on material disagreement** and raise a flag.

## Design
- **`models/params.py`** (pure — `models/` holds the ICR/ISF estimators):
  - `fit_icr_isf(rows) -> IcrIsfFit`, `rows = [(pre_bg, carbs_g, total_bolus,
    post_bg), …]`. Response `y = post_bg − pre_bg`; design `[carbs_g, total_bolus,
    1]`.
    - **Unconstrained** fit (`numpy.linalg.lstsq`) → `unconstrained_beta_ins =
      −coef[bolus]`.
    - **Constrained** fit (`scipy.optimize.lsq_linear`, bounds: `b_carb ≥ 0`,
      `b_bolus ≤ 0`, intercept free) → `beta_carb ≥ 0`, `beta_ins = −b_bolus ≥ 0`.
    - **INV-8** wired: `inv8_beta_insulin_non_negative(beta_ins)` on the value that
      is actually used.
    - `confounding_warning = unconstrained_beta_ins < 0`; when true, a prominent
      `WARNING` naming confounding-by-indication is logged.
    - `isf = beta_ins`; `icr = isf/beta_carb` (`None` if `beta_carb ≈ 0`).
  - `cross_check_isf(ols_isf, correction_isf, *, tol_frac=0.20) -> IsfCrossCheck` —
    material disagreement if `|ols − corr|/corr > tol_frac`; on disagreement the
    chosen ISF is the **correction-event** value and `flagged = True` (they are
    unconfounded).
- **`data/repositories.py::fit_icr_isf_from_training(session)`** — builds rows from
  `get_training_set` (valid meals with an outcome; `total_bolus = meal_bolus +
  correction_bolus`) and calls `fit_icr_isf`.
- Requires ≥ 3 rows (intercept + 2 coefficients); fewer raises `ValueError`.

## Written safety argument (why INV-8 holds) [SAFETY]
1. **Constraint, always.** The applied fit is `lsq_linear` with `b_bolus ≤ 0`, so
   `beta_ins = −b_bolus ≥ 0` by construction — the constraint is not optional and
   is re-asserted by `inv8_beta_insulin_non_negative` (`core/safety.py`, unchanged).
2. **The negative is reported, never swallowed.** When the *unconstrained* fit wants
   `β_ins < 0` (insulin appearing to raise glucose), the confounding-by-indication
   warning fires and the flag is set — the signal about the data is surfaced to the
   operator, not hidden by the constraint.
3. **Unconfounded cross-check wins.** The OLS ISF is confounded by construction; the
   correction-event ISF (S-502) is not. On material disagreement the correction
   value is preferred and flagged, so the confounded estimate can never quietly set
   the denominator.
4. **No dose path touches this.** ADR-10: the prescriptive module uses the clinical
   formula (causal by construction); the ML never touches a dose. This fit informs
   ICR/ISF review only.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_params.py`:
- **Clean recovery (golden):** data generated as `delta = 3·carbs − 30·bolus`
  (carbs/bolus varied independently) ⇒ `beta_carb ≈ 3`, `beta_ins ≈ 30`,
  `isf ≈ 30`, `icr ≈ 10`, `confounding_warning is False`.
- **★ Confounded (the single most important test):** data where **bolus positively
  correlates with post-meal BG** (`delta = 3·carbs + 10·bolus`) ⇒
  `unconstrained_beta_ins < 0`, **`confounding_warning is True`** (and a WARNING is
  logged naming confounding-by-indication), and the applied **`beta_ins ≥ 0`**
  (INV-8 holds). This is the realistic hypo pathway, blocked.
- **INV-8 invariant:** the returned `beta_ins` is `≥ 0` on both datasets.
- **Cross-check:** `ols=45, corr=30` (disagree > 20%) ⇒ prefer correction, flagged;
  `ols=31, corr=30` (agree) ⇒ not flagged.
- **Too few rows raises `ValueError`.**

**RED evidence:** `models/params.py` does not exist ⇒ import errors before impl.

**Adversarial angle:** the trap is accepting the unconstrained fit "because the data
says so" — which learns insulin raises glucose and, inverted into a dose, drives a
low she cannot feel. The confounded test asserts both halves: the constraint holds
**and** the warning fired, so the constraint can never silently paper over a data
problem.
