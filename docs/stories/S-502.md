# S-502 [SAFETY] — ISF from correction events

**Epic:** 5 (Baseline & Parameters) · **Safety story:** Yes · **Status:** In progress
**Requirements:** REQ-033 · **Consumes:** S-306b (`iob_at_start`), the S-306
clean-event filter.

> **ISF is the most dangerous number in the system.** It sits in the denominator of
> the correction term, and an ISF that is *too low* causes **over-dosing** → a low
> she cannot feel. The correction events are the only *unconfounded* read on it — so
> deriving ISF from them is high-value, and every guard here (the ≥5-event gate, the
> never-silent-swap rule, the ≤0 hard-stop) exists so a bad derivation can never
> quietly replace a safe default.

## Story
Derive ISF from the clean correction events (07 §6), gate it behind a minimum
sample size, **report both** the current and derived value rather than swapping
silently, and **refuse** a non-positive derived ISF.

## Requirement source
- **REQ-033 / 07 §6** — `derived_ISF = mean((bg_before − bg_after)/units)` over
  events with `iob_at_start < 0.5 AND food_in_window == False`; **≥5 valid events**
  before it may override the default; **never silently swaps** (report current and
  derived); **derived ISF ≤ 0 → raise**, do not apply.

## Design
- **`models/isf.py`** (pure — 06 §arch, `models/` holds the ICR/ISF estimators):
  - `MIN_CLEAN_EVENTS = 5`.
  - `derive_isf(triples, *, current_isf, current_source) -> ISFResult` where
    `triples` is `[(bg_before, bg_after, units), …]` for the clean events.
    - No events ⇒ `ISFResult(n=0, derived=None, applied=False, isf=current,
      source=current)`.
    - Compute `derived = mean((bef − aft)/u)`.
    - **`derived ≤ 0` ⇒ raise `SafetyViolation`** (insulin appearing not to lower
      glucose — bad data / confounding; never applied).
    - **`n ≥ 5` ⇒ applied**: `isf = derived`, `isf_source = "derived"`.
    - **`n < 5` ⇒ reported, not applied**: `isf`/`source` stay the current values,
      but `derived` is carried so the operator sees it (never a silent swap).
  - `ISFResult` carries `n_clean`, `derived_isf`, `applied`, `isf`, `isf_source`,
    `events_needed` — everything the operator dashboard needs to show both numbers.
- **`data/repositories.py::derive_isf_from_correction_events(session, *,
  current_isf, current_source)`** — bridges the clean-event accessor to the pure
  estimator: takes `get_clean_correction_events`, keeps only those with a **+4 h
  reading** (`bg_after is not None` — an event without its follow-up cannot
  contribute to ISF), and calls `derive_isf`.

## Written safety argument (why this is safe) [SAFETY]
1. **Unconfounded input only.** The estimator sees only events already filtered to
   `food_in_window == False AND iob_at_start (known) < 0.5` (07 §6, enforced by
   `get_clean_correction_events` since S-306/S-306b) — no food and negligible prior
   insulin, so `(bg_before − bg_after)/units` is a clean read on ISF.
2. **Sample-size gate.** Below 5 clean events the derived value is **reported, not
   applied** — the provisional default (ISF 30) stays in force. A handful of noisy
   events can never move the most dangerous number.
3. **Never a silent swap.** `derive_isf` returns *both* the current and the derived
   value; applying it is an explicit, operator-visible step. Nothing here mutates
   `patient_profile` — a change is a new version (REQ-054), decided by the operator.
4. **Non-positive is a hard stop.** A derived ISF ≤ 0 means insulin appears not to
   lower glucose — confounding or bad data. It **raises**, never applies, so a
   nonsensical (and dangerously low/negative) ISF can never reach the denominator.

## TDD strategy (SDET, written first — seen to fail)
`tests/unit/test_isf.py`:
- **4 clean events ⇒ default retained, derived reported:** `applied is False`,
  `isf == current_isf`, `isf_source` unchanged, `derived_isf` is the mean.
- **5 clean events ⇒ applied:** `applied is True`, `isf == derived`,
  `isf_source == "derived"`, `n_clean == 5`.
- **Golden mean:** five events each implying ISF 30 ⇒ `derived_isf == 30.0`.
- **★ Derived ISF ≤ 0 raises:** an event set whose mean `(bef−aft)/u ≤ 0`
  (BG rose after a correction) ⇒ `SafetyViolation`, even at n ≥ 5.
- **No events ⇒ default, not applied, `derived_isf is None`.**

`tests/integration/test_isf_derivation.py`:
- `derive_isf_from_correction_events` includes only `food_in_window == False`,
  `iob_at_start < 0.5`, **and `bg_after is not None`** events; a followup-pending
  event (bg_after NULL) is excluded; 5 qualifying ⇒ applied.

**RED evidence:** `models/isf.py` / `derive_isf_from_correction_events` do not exist
⇒ import errors before impl.

**Adversarial angle:** the tempting shortcuts are (a) applying a derived ISF from 1–2
events (the gate blocks it), (b) silently overwriting the profile (nothing here
writes it; both values are surfaced), and (c) letting a ≤0 derived through "because
it's just a number" — which would put a near-zero ISF in the denominator and
massively over-dose. The ≤0 hard-stop kills that.
