# S-804 [SAFETY] — Patient risk readout

**Epic:** 8 (Guardrails & Output) — **closes EPIC 8** · **Safety story:** Yes, the first
patient-reachable INV-2 surface · **Status:** Done · **Requirements:** REQ-040,
**INV-2**

> **This is the first thing she actually sees, and she may be reading it while low.** So
> it leads with the one question that matters — *is a hypo likely?* — in plain language,
> never colour alone; a refusal is a rendered answer, not a blank; and it **never tells
> her to dose** (that is the prescriptive module, behind Gate 2). And it does not exist at
> all until Gate 1 is earned: at 149 valid meals the surface refuses, with no lever to
> force it open.

## Story
Assemble the patient-facing risk readout from a guarded prediction (S-801), behind Gate 1
(S-703) and the kill switch (S-803). **Hypo risk is the headline**; the language is plain;
a refusal (or a suppressed/gated state) is a **rendered state**, not an error or a blank;
and the readout carries **no advice** — no dose, no "take insulin/carbs". Before Gate 1
passes the surface raises, and there is no bypass.

## Requirement source
- **REQ-040 / INV-2** — no patient-visible model output before Gate 1.
- **Backlog AC/TDD** — *Hypo risk is the headline. Plain language. Refusal is a rendered

- **Accessibility (02/§a11y, audit watch-list)** — hypo risk the headline, **no

## Design
`prescribe/readout.py` (the gated-output package; imports `prescribe.gates` for INV-2 and
`models.guardrails` for the guarded result):

- **`ReadoutKind(StrEnum)`** — `PREDICTION`, `REFUSAL`, `CONFLICT`, `BASELINE_FALLBACK`.
- **`PatientReadout`** — `headline: str` (always hypo-risk-first), `hypo_risk: str` (a
  **text** label: `elevated` / `reduced` / `in_range` / `unknown`), `severity: str` (a
  **text** label, not a colour: `high` / `moderate` / `low` / `none` / `unknown`),
  `kind`, `state: int | None`, `baseline_state: int | None`, `body: str` (plain language).
  There is **no** `advice` / `dose` / `bolus` / `units` field — by construction the
  readout cannot carry a dosing instruction.
- **`build_patient_readout(*, gate1, guarded, kill_switch_tripped, baseline_state) ->
  PatientReadout`**:
  1. **`require_gate1(gate1)` first** — raises `GateNotPassed` when Gate 1 is closed
     (n < 150, or the model has not beaten the baseline). No bypass parameter; no env var
     or flag is read.
  2. **Kill switch tripped** ⇒ `BASELINE_FALLBACK` — ML suppressed, hypo risk framed from
     the baseline state, body says the model is paused and the baseline is shown.
  3. **Refusal** (`guarded.refused`) ⇒ `REFUSAL` — a rendered state with plain body (e.g.
     "Not confident enough to predict this one"), `hypo_risk = "unknown"`.
  4. **Conflict** (`guarded.conflict`) ⇒ `CONFLICT` — both states shown, **no winner**
     (`state = None`), hypo risk taken from the **more cautious** (lower) of the two.
  5. Otherwise ⇒ `PREDICTION` — hypo risk from the predicted state.
- **Hypo framing:** states 1–2 (BG < 80) ⇒ `elevated` hypo risk / `high` severity; state 3
  ⇒ `in_range` / `low`; states 4–5 ⇒ `reduced` (hyper, not hypo) / `moderate`. The
  headline always names hypo risk first, whatever the state.

**Presentation note (deferred):** the HTML rendering of `PatientReadout` (a Jinja
template + route + axe a11y test) lands when a live model is wired to real meals (there is
no patient-visible prediction to render before then — same gate discipline as S-703). The
`severity`/`hypo_risk` **text** labels mean any renderer already has a non-colour signal
to show; the readout data cannot be colour-only.

## Written safety argument (why no ungated output and no advice can reach her) [SAFETY]
1. **Gate 1 is the first line, un-bypassable.** `build_patient_readout` calls
   `require_gate1` before it constructs anything; at n = 149 that raises `GateNotPassed`
   and nothing is returned. The signature exposes no override, and the body reads no env
   var or flag — INV-2's "no patient output before Gate 1" is enforced here, made
   executable by a no-bypass test.
2. **A dose cannot appear in a risk readout.** `PatientReadout` has no `advice` / `dose` /
   `bolus` / `units` field; there is no code path that puts a dosing instruction on it. The
   prescriptive module (Gate 2, EPIC 9) is the *only* place a dose is ever produced, and it
   is a separate surface behind a separate gate.
3. **Silence is a rendered state, never a blank.** Refusal, conflict, and kill-switch
   suppression each produce a `PatientReadout` with a plain-language `body` and a hypo-risk
   headline — she always sees a definite answer, never an empty screen or a raw error.
4. **The signal is textual.** `hypo_risk` and `severity` are text labels, so the readout
   never depends on colour alone — legible to someone impaired by a low, and to a screen
   reader.
5. **Fail-safe under the kill switch.** When the switch is tripped the readout shows the
   ML-free baseline, not a stale model state — degrading to the arithmetic she already
   trusts.

## TDD strategy (SDET, written first — seen to fail)
`tests/safety/test_readout.py`:
- **★ n = 149 ⇒ surface raises.** `gate1` closed (149 valid meals) ⇒
  `build_patient_readout` raises `GateNotPassed`.
- **★ No bypass.** No `force`/`override`/`skip_gate` parameter on `build_patient_readout`;
  bypass-looking env vars do not open it.
- **Hypo risk is the headline.** For a State-2 prediction the `headline` names hypo/low
  first and `hypo_risk == "elevated"`, `severity == "high"`; for State 3 it is `in_range`.
- **Refusal is a rendered state.** A refused guarded result ⇒ `kind == REFUSAL`, non-empty
  plain `body`, `state is None`, `hypo_risk == "unknown"` — not a blank, not an exception.
- **★ Never advice.** `PatientReadout` has no `advice`/`dose`/`bolus`/`units` attribute,
  and no `body` contains a dosing directive ("units", "inject", "take … insulin").
- **Kill switch ⇒ baseline fallback.** `kill_switch_tripped=True` ⇒
  `kind == BASELINE_FALLBACK`, `baseline_state` shown, body says the model is paused.
- **Conflict shows both, no winner.** A conflicting guarded result ⇒ `kind == CONFLICT`,
  both states present, `state is None`, hypo risk from the more cautious state.
- **Signal is textual.** `severity` and `hypo_risk` are non-empty strings (a11y — not
  colour-only).

**RED evidence:** `prescribe/readout.py` does not exist ⇒ import error before impl.

**Adversarial angle:** the tempting shortcut is to render the arg-max state directly to the
patient "so the screen isn't empty", skipping the gate — which is exactly ungated model
output, forbidden by INV-2. The n=149 and no-bypass tests make the gate the only door, and
the never-advice tests make it structurally impossible for a dose to ride along on a risk
screen.
