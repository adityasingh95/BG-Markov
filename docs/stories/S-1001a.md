# S-1001a — Operator shadow report card (read-only)

**Epic:** 10 · **Safety story:** No — but it carries a safety *rule* (see below) ·
**Status:** In progress · **Requirements:** REQ-055 · **Records:** DL-044 (the split),
**DL-042** (badges are relative, never invented) · **Rollback baseline:** `7a7c3bf`

> Discharges the S-805 deferred presentation note. `build_shadow_report` has returned a
> tested data structure since S-805; nothing rendered it. This is the screen the operator
> reads before deciding whether she may see the model at all.

## Story
The operator can look at one page and answer: *is this model any good, is it honest, and is
there anything alarming about it?* — without being a statistician, and without being misled.

## The rule this screen carries

`05b §7.2` asks for every metric three ways together — **value, plain-language
interpretation, technical term** — plus a verdict badge. Only three metrics have a bar
defined anywhere in the project:

| Metric | Its bar | Where the bar comes from |
|---|---|---|
| Catches her lows | the clinical baseline | the Gate-1 condition itself |
| False alarms | `target_far` (0.10) | already a parameter of `hypo_recall_at_far` |
| Percentages honest | the DL-042 rule | operator-approved (OQ-9) |
| Insulin makes sense | `β_insulin < 0` | INV-8 — a yes/no alarm |

For the rest — Brier, MAE, off-by-one, severe error, Clarke — **no absolute bar exists**.
Per DL-042, badges are therefore **relative to the clinical baseline**: *Better / About the
same / Worse* than the arithmetic she would use with no model at all. Nothing invented, and
it is the question that actually matters.

**Rows with no baseline figure carry `NOT_COMPARED` and no verdict.** Not a neutral-looking
badge, not a hopeful one — the absence is shown. An invented `[Good]` on this screen would
read as authority it has not earned and would be indistinguishable from the four that are
real.

**One sanctioned absolute:** the Clarke grid's **D/E** zones are dangerous by the measure's
own construction — a D is *"failed to detect a low"*, which is dangerous regardless of any
threshold anyone picks. Those are flagged directly.

## Design

### `api/presenters.py` — pure view-model construction
No DB, no I/O, no model fitting. Turns domain objects into rows a template renders.

```python
class Verdict(str, Enum):
    BETTER | SAME | WORSE | NOT_COMPARED | OK | ALARM

@dataclass(frozen=True)
class MetricRow:
    key, heading, value, plain, technical, verdict, verdict_label, comparison

@dataclass(frozen=True)
class BaselineComparison:      # every field optional; None ⇒ NOT_COMPARED
    hypo_recall, brier, mae_mgdl, off_by_one, severe_error, clarke_danger

shadow_rows(report, *, baseline, calibration) -> tuple[MetricRow, ...]
```

- **Comparison is exact, with no invented tolerance.** `BETTER` iff strictly better,
  `WORSE` iff strictly worse, `SAME` only on exact equality. This mirrors the Gate-1 rule
  (`model_hypo_recall > baseline_hypo_recall`, strict) rather than introducing a second,
  looser notion of "beats". `SAME` will therefore be rare — which is honest; the numbers are
  on the row for anyone who wants to judge the margin themselves.
- **Direction is per-row.** Recall higher-is-better; MAE, Brier, off-by-one, severe, Clarke
  danger lower-is-better. Getting this backwards would invert every badge on the page, so it
  is a named field, not an inline `if`.
- **`report is None` is a first-class state**, not an error. Today there is no model and no
  data; the page must say so plainly.

### `GET /operator/shadow` + `api/templates/operator_shadow.html`
- Operator nav only. Reachable from `/operator`, absent from the patient-facing pages.
- Gate 1 status shown live. **Gate 2 must not appear** — it is retired (S-1011/DL-035), and
  showing it would imply a dose control that does not exist.
- Full charts behind a `<details>` **detailed charts** disclosure (`05b §7.2`) — available,
  not the first thing.
- **No dose, ever.** No plain-accuracy figure anywhere.

## TDD strategy (SDET first — written and seen to fail)
`tests/unit/test_presenters.py`:
- **★ No baseline figure ⇒ `NOT_COMPARED` and an empty verdict label.** The row must not
  invent a verdict, and must not borrow a neighbouring row's.
- **★ Direction is respected:** a *lower* MAE than baseline is `BETTER`; a *higher* recall is
  `BETTER`. A single inverted comparison would flip every badge on the page.
- Exact comparison: recall 0.7100 vs 0.7099 ⇒ `BETTER`, not `SAME`.
- **★ `β_insulin < 0` ⇒ `ALARM`** and the row is present even when everything else is fine.
- **★ Any Clarke D or E ⇒ `ALARM`** regardless of baseline — dangerous by construction.
- Calibration row reflects the S-1012 verdict and carries its plain-language `reason`.
- Every row carries all three of value, plain, technical — none empty.
- **★ No row anywhere contains the word "accuracy"**, in any field.
- `report=None` ⇒ an explicit empty state, no exception, no rows implying a fitted model.

`tests/integration/test_operator_shadow.py`:
- **★ Renders with an empty database** — no model, no predictions — 200 and a plain
  "nothing to show yet" state. This is today's actual state and the most likely thing to
  crash.
- Renders a full report; the headline metric is hypo recall.
- **★ `β_insulin < 0` produces visible alarm text in the HTML**, not a silent pass.
- **★ No dose-like field anywhere in the DOM** (`dose`, `bolus`, `units`, `inject`).
- **★ "accuracy" appears nowhere** in the rendered page or the template source.
- **Gate 2 appears nowhere** — no "gate 2", no "prescriptive".
- Gate 1 status is rendered with all **five** conditions named.

`tests/a11y/test_operator_shadow.py`:
- `axe` passes; no horizontal overflow at 200% zoom; verdicts are **text**, never colour
  alone (`05b §2`).

**RED evidence:** `api.presenters` does not exist; `GET /operator/shadow` 404s.

**Adversarial angle.** The temptation on this screen is a **reassuring default** — a badge
that renders as neutral-positive when the data is missing, a row quietly dropped when it
cannot be computed, an "accuracy" figure added later because it is easy to explain. Each
would make the screen *feel* more complete while being less true, on the page a human uses
to decide whether to put someone who cannot feel a low in front of a model.
