## Findings (most severe first)

**No blocker, major, or minor actionable findings.** EPIC 5 is TDD-honest, toolchain-green, and
its safety wiring holds under independent adversarial re-derivation. The items below are recorded
as **observations / watch-next**, not remediation work — they are non-actionable at this commit
because no live consumer exists, and forcing them now would be inventing work.

**[OBSERVATION — watch, not a finding] O1 — `fit_icr_isf.icr` can degenerate toward 0 in the
fully-confounded case.** When confounding clamps `β_ins` to 0, `icr = β_ins/β_carb = 0`
(`models/params.py:82`, guarded only against `β_carb≈0`, not against `β_ins=0`). A future consumer
computing `carbs/icr` (07 §4 baseline shape) would raise `ZeroDivisionError` — **loud, not silent**,
so it is not the failure mode this project fears, and there is **no live consumer** today (baseline
takes `icr` from `patient_profile`, not from this fit). Why it matters for *her*: when the ICR/ISF
fit is eventually wired into a recommendation (EPIC 9), a degenerate ICR of ~0 must surface as a
refusal/flag, not a crash mid-dose. Suggested owner (later): Dev, at the wiring story. Recorded so
it is not forgotten.

**[OBSERVATION — watch, not a finding] O2 — INV-7 (hypo-rescued meals) is not exercised by the S-503
OLS.** `fit_icr_isf` takes rows directly; there is no live meal→OLS wiring yet, so the "exclude
rescued meals from the outcome regression, retain as hypo events" contract has no call site here.
INV-7's function exists and is tested in isolation; it must gate the row set when the OLS is wired to
real meals (EPIC 9). Not actionable now. Suggested owner (later): Dev/BA at the wiring story.
