## Findings (most severe first)

**[SEV: minor] F1 — the CI coverage gate does not measure `features/`, the code EPIC 4 is entirely about.**
Claim vs reality: DoD requires "Coverage ≥ 90% on touched `core/`", and `pyproject.toml:107-111`
sets `source = ["core"]` with the comment *"Expand this list as features/, models/, prescribe/ are
introduced by later epics. The 90% gate applies to whatever is listed here."* EPIC 4 introduced
`features/` (IOB, basal, exercise, CV, pipeline) but neither `pyproject.toml` nor
`.github/workflows/ci.yml:41` (`pytest --cov=core --cov-fail-under=90`) was expanded. Evidence:
grep of `ci.yml` shows `--cov=core` only; `pyproject` source unchanged. The code *is* well-covered
today — my `--cov=core --cov=features` run measured `features/` at 99% (only `cv.py:39`, the
too-few-days `ValueError`, uncovered) — so **this is not a live coverage hole**, it is a gate that
has stopped watching. Why it matters for *her*: the leakage/CV/IOB machinery in `features/` is the
part of the system most able to be "quietly wrong"; a coverage gate that silently excludes it means
a future refactor could delete a test path (or a branch) in exactly that machinery and CI would stay
green. Suggested owner: **Dev** (add `features` to the coverage source and the CI `--cov` invocation;
optionally cover `cv.py:39`), with **BA** noting the gate expansion in the decision log per the
pyproject comment's own instruction.

**[SEV: minor] F2 — `iob_at` counts a clock-skew (future-dated) bolus as full IOB, deviating from the spec §2 reference, with no decision-log record.**
Claim vs reality: `docs/07-clinical-model-spec.md` §2 gives the reference `iob_at` with the guard
`if 0 < (ts - b.datetime)/60 < td`, i.e. a bolus at-or-after `ts` contributes **zero**. The shipped
`features/iob.py:46-59` omits that filter and relies on `iob_fraction(t<=0)=1.0`, so a future-dated
bolus contributes its **full** units. This is *intentional and tested* —
`tests/unit/test_iob.py:96-102` (`test_iob_at_ignores_fully_decayed_and_future_boluses`) asserts a
future bolus yields `1.0 * units`. It is also **safe-direction** (over-estimating IOB reduces any
downstream dose and only *excludes* an event from the clean-ISF set) and cannot arise in the live
path, because `boluses_before(session, at)` filters `BolusLog.datetime < at` (strictly before), so
`iob_at_start_at` never sees a same-instant or future bolus (`data/repositories.py:125-137`). Why it
matters: precedence doc 07 wins on clinical/model matters (CLAUDE.md); a deliberate divergence from
its reference implementation — even a safe one — is exactly the kind of thing the decision log exists
to capture so a later reader does not "fix" the pure function back toward the spec and change
behaviour. Suggested owner: **BA** (record the deliberate deviation and its safe-direction rationale
in the decision log, or ask Dev to align `iob_at` to the §2 filter — either is fine; the point is it
should be a recorded decision, not an undocumented delta).
